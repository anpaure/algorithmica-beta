Cache-Oblivious Algorithms

A cache-aware algorithm chooses tiles, buffers, or fan-in using known $M$ and $B$. A cache-oblivious algorithm contains no parameters tuned to those values, yet its access order can still have an asymptotically good block-transfer count.

The usual analysis uses an ideal fully associative cache with $M$ words, blocks of $B$ consecutive words, and optimal replacement. Results often assume a tall cache, $M=\Omega(B^2)$. These are proof assumptions, not a description of every CPU. The value is that one recursive access order can be analyzed independently at L1, L2, the last-level cache, and another managed boundary.

Cache-oblivious does not mean automatically cache-efficient. A random permutation is oblivious to $M$ and $B$ too. The recursion and data layout must ensure that subproblems become contiguous and remain reusable once they fit.

Frigo, Leiserson, Prokop, and Ramachandran formalized the model and its matrix bounds in “Cache-Oblivious Algorithms”. The term is also unrelated to data-oblivious algorithms, which hide access patterns for security.

#Rectangular Matrix Transposition

Let $A$ be a row-major $m\times n$ matrix and let $D$ be a separate row-major $n\times m$ destination. A simple loop can read rows of $A$ contiguously or write rows of $D$ contiguously, but not both. When the stride is large, the other side may use only one element from each transferred block.

Recursive transposition divides the longer dimension. Eventually a source tile and its destination tile are both small enough to remain cached, even though the program never tests $M$ or $B$.

The following implementation handles rectangular and odd dimensions. Source and destination must not overlap:

#include <cstddef>
#include <limits>
#include <span>
#include <stdexcept>

std::size_t checked_matrix_area(std::size_t rows,
                                std::size_t columns) {
    if (rows != 0
        && columns > std::numeric_limits<std::size_t>::max() / rows)
        throw std::length_error("matrix size overflow");
    return rows * columns;
}

void transpose_tile(std::span<const double> source,
                    std::span<double> destination,
                    std::size_t source_columns,
                    std::size_t destination_columns,
                    std::size_t row_begin,
                    std::size_t row_end,
                    std::size_t column_begin,
                    std::size_t column_end) {
    const std::size_t rows = row_end - row_begin;
    const std::size_t columns = column_end - column_begin;
    if (rows == 0 || columns == 0)
        return;

    if (rows <= 16 && columns <= 16) {
        for (std::size_t row = row_begin; row < row_end; ++row)
            for (std::size_t column = column_begin;
                 column < column_end;
                 ++column)
                destination[column * destination_columns + row]
                    = source[row * source_columns + column];
        return;
    }

    if (rows >= columns) {
        const std::size_t middle = row_begin + rows / 2;
        transpose_tile(source, destination,
                       source_columns, destination_columns,
                       row_begin, middle, column_begin, column_end);
        transpose_tile(source, destination,
                       source_columns, destination_columns,
                       middle, row_end, column_begin, column_end);
    } else {
        const std::size_t middle = column_begin + columns / 2;
        transpose_tile(source, destination,
                       source_columns, destination_columns,
                       row_begin, row_end, column_begin, middle);
        transpose_tile(source, destination,
                       source_columns, destination_columns,
                       row_begin, row_end, middle, column_end);
    }
}

void transpose_out_of_place(std::span<const double> source,
                            std::span<double> destination,
                            std::size_t rows,
                            std::size_t columns) {
    const std::size_t area = checked_matrix_area(rows, columns);
    if (source.size() != area || destination.size() != area)
        throw std::invalid_argument("matrix extent mismatch");

    transpose_tile(source, destination, columns, rows,
                   0, rows, 0, columns);
}

The constant $16$ is only a recursion-overhead cutoff; it does not describe a cache. Recursing to individual elements gives the same asymptotic access order.

Under the ideal-cache and tall-cache assumptions, the transfer count is

$$ Q_{\mathrm{transpose}}(m,n) =\Theta\left(1+\frac{mn}{B}\right). $$

This is optimal up to constants because the algorithm must read and write $\Theta(mn)$ elements. In-place rectangular transposition is a different and substantially more complicated permutation problem; the code above makes no in-place claim.

#Matrix Multiplication by Three-Way Recursion

For row-major matrices

$$ C_{ij}=\sum_{k=0}^{p-1}A_{ik}B_{kj}, $$

where $A$ is $m\times p$, $B$ is $p\times n$, and $C$ is $m\times n$. A fixed triple-loop order makes at least one large matrix access unfriendly for some shapes. Cache-aware libraries solve this with tuned tiles.

A cache-oblivious version recursively splits the largest of the row, column, and reduction ranges. Splitting rows or columns creates independent output regions. Splitting the reduction range performs two contributions to the same output region, in order.

The code below initializes $C$ and supports arbitrary dimensions. The output span must not overlap either input span:

#include <algorithm>
#include <cstddef>
#include <limits>
#include <span>
#include <stdexcept>

std::size_t checked_matrix_size(std::size_t rows,
                                std::size_t columns) {
    if (rows != 0
        && columns > std::numeric_limits<std::size_t>::max() / rows)
        throw std::length_error("matrix size overflow");
    return rows * columns;
}

void multiply_add_region(std::span<const double> left,
                         std::span<const double> right,
                         std::span<double> output,
                         std::size_t inner,
                         std::size_t columns,
                         std::size_t row_begin,
                         std::size_t row_end,
                         std::size_t column_begin,
                         std::size_t column_end,
                         std::size_t inner_begin,
                         std::size_t inner_end) {
    const std::size_t row_count = row_end - row_begin;
    const std::size_t column_count = column_end - column_begin;
    const std::size_t inner_count = inner_end - inner_begin;

    if (row_count == 0 || column_count == 0 || inner_count == 0)
        return;

    if (row_count <= 16
        && column_count <= 16
        && inner_count <= 16) {
        for (std::size_t row = row_begin; row < row_end; ++row) {
            for (std::size_t k = inner_begin; k < inner_end; ++k) {
                const double value = left[row * inner + k];
                for (std::size_t column = column_begin;
                     column < column_end;
                     ++column)
                    output[row * columns + column]
                        += value * right[k * columns + column];
            }
        }
        return;
    }

    if (row_count >= column_count
        && row_count >= inner_count
        && row_count > 1) {
        const std::size_t middle = row_begin + row_count / 2;
        multiply_add_region(left, right, output, inner, columns,
                            row_begin, middle,
                            column_begin, column_end,
                            inner_begin, inner_end);
        multiply_add_region(left, right, output, inner, columns,
                            middle, row_end,
                            column_begin, column_end,
                            inner_begin, inner_end);
        return;
    }

    if (column_count >= inner_count && column_count > 1) {
        const std::size_t middle = column_begin + column_count / 2;
        multiply_add_region(left, right, output, inner, columns,
                            row_begin, row_end,
                            column_begin, middle,
                            inner_begin, inner_end);
        multiply_add_region(left, right, output, inner, columns,
                            row_begin, row_end,
                            middle, column_end,
                            inner_begin, inner_end);
        return;
    }

    const std::size_t middle = inner_begin + inner_count / 2;
    multiply_add_region(left, right, output, inner, columns,
                        row_begin, row_end,
                        column_begin, column_end,
                        inner_begin, middle);
    multiply_add_region(left, right, output, inner, columns,
                        row_begin, row_end,
                        column_begin, column_end,
                        middle, inner_end);
}

void matrix_multiply(std::span<const double> left,
                     std::span<const double> right,
                     std::span<double> output,
                     std::size_t rows,
                     std::size_t inner,
                     std::size_t columns) {
    if (left.size() != checked_matrix_size(rows, inner)
        || right.size() != checked_matrix_size(inner, columns)
        || output.size() != checked_matrix_size(rows, columns))
        throw std::invalid_argument("matrix extent mismatch");

    std::fill(output.begin(), output.end(), 0.0);
    multiply_add_region(left, right, output, inner, columns,
                        0, rows, 0, columns, 0, inner);
}

The routine performs $\Theta(mpn)$ arithmetic operations. Its advantage is the order of those operations, not a change in algebra.

For square $n\times n$ matrices, group the recursion into levels that halve all three index ranges. There are eight half-size multiplication subproblems. Once three participating submatrices fit in cache, a base subproblem moves $\Theta(M/B)$ blocks and performs $\Theta(M^{3/2})$ multiply-adds. The number of such base subproblems is

$$ \Theta\left(\left(\frac{n}{\sqrt M}\right)^3\right). $$ Multiplying gives the cache-miss bound $$ Q_{\mathrm{multiply}}(n) =\Theta\left( \frac{n^2}{B} +\frac{n^3}{B\sqrt M} \right). $$ The scan term accounts for reading inputs and writing output. For rectangular matrices, the corresponding bound is $$ \Theta\left( 1+\frac{mp+pn+mn}{B} +\frac{mpn}{B\sqrt M} \right). $$

The old-style recurrence $8Q(n/2)+O(n^2/B)$ is easy to misuse by charging whole-matrix traffic at every recursion node. The fitting-subproblem argument counts what must actually enter a cache after locality begins to pay off.

#Theory and Production Kernels

An ideal-cache bound does not account for SIMD width, instruction scheduling, hardware prefetch, TLBs, associativity conflicts, NUMA placement, or parallel false sharing. Production matrix libraries use carefully packed and architecture-tuned kernels, often inside a hierarchy of tiles.

Cache-oblivious recursion remains useful as a portable outer decomposition and as a way to reason about every cache level at once. A practical hybrid can stop at a fixed small threshold and call a tuned kernel; the mathematical partition still does not encode cache capacity or line size.

Algebraic algorithms such as Strassen change the number of multiplications and introduce separate numerical and memory trade-offs. They are orthogonal to fixing the access order of classical multiplication and should be analyzed with their own recurrence rather than attached to the code above.

The core technique is simple but exacting: recurse on views, split dimensions without dropping odd rows or columns, and accumulate every reduction interval exactly once. Once those invariants hold, the cache analysis has something correct to describe.
