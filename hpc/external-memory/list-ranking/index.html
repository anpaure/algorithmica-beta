List Ranking

A linked list is easy to traverse and difficult to lay out. If successor nodes occupy unrelated blocks, following $N$ pointers can cause $\Theta(N)$ I/Os even though the records themselves occupy only $\Theta(N/B)$ blocks.

List ranking converts that pointer structure into numeric positions without assuming that list order matches storage order.

#Define the Rank First

Let every record contain a unique identifier, a successor identifier or null, and a nonnegative edge weight $w(v)$. The records must form one acyclic chain with exactly one head and one tail.

This chapter defines the rank as weighted distance from a node to the tail:

$$ \operatorname{rank}(\text{tail})=0, $$ and for every other node $$ \operatorname{rank}(v) =w(v)+\operatorname{rank}(\operatorname{next}(v)). $$

Use the harmless convention $w(\text{tail})=0$.

For an unweighted list, set every non-tail edge weight to one. The rank is then the number of links after the node: the tail has rank zero, its predecessor has rank one, and the head has rank $N-1$. This convention is different from a prefix position measured from the head, so an implementation must not alternate between the two.

Before ranking untrusted records, validate the structural contract. Duplicate identifiers, multiple predecessors, missing successors, multiple components, or a cycle make the recurrence undefined or describe a different problem.

#Pointer Jumping as a Baseline

Pointer jumping stores for each node a current successor $s_i(v)$ and accumulated distance $d_i(v)$. Initially,

$$ s_0(v)=\operatorname{next}(v), \qquad d_0(v)=w(v). $$ One round joins every record with its current successor and doubles the covered distance: $$ \begin{aligned} d_{i+1}(v) &= d_i(v)+d_i(s_i(v)),\\ s_{i+1}(v) &= s_i(s_i(v)). \end{aligned} $$

The tail contributes zero, and a null successor remains null. After $\lceil\log_2 N\rceil$ rounds, every node has jumped to the tail and $d_i(v)$ is its rank.

With records sorted by identifier, each round can be implemented as a sort–merge join. It is parallel and conceptually clean, but it costs

$$ O(\operatorname{Sort}(N)\log N) $$

I/Os because all $N$ records participate in every round. Randomized contraction removes this extra logarithm.

#Contract an Independent Set

Assign an independent random bit $b(v)$ to every node. Keep the head and tail, and select an internal node $v$ for removal when

$$ b(v)=1 \quad\text{and}\quad b(\operatorname{next}(v))=0. $$

Two consecutive nodes cannot both satisfy the rule: the shared bit would need to be both zero and one. Each eligible internal node is selected with probability $1/4$, so the expected remaining list has at most $3N/4+O(1)$ nodes.

Suppose selected node $v$ lies between retained nodes $u$ and $x$:

$$ u\xrightarrow{\,w(u)\,}v \xrightarrow{\,w(v)\,}x. $$ Contract it by replacing the two edges with $$ \operatorname{next}'(u)=x, \qquad w'(u)=w(u)+w(v). $$ The weighted distance from $u$ to the tail is unchanged. Store the restoration record $(v,x,w(v))$, recurse on the contracted list, and reconstruct the removed rank with $$ \operatorname{rank}(v) =w(v)+\operatorname{rank}(x). $$

The independent-set property guarantees that $u$ and $x$ survived this level, so both contraction and restoration use one retained neighbor on each required side.

#Performing a Level with Sorts

The list is stored as tables keyed by node identifier, not as in-memory pointers. A contraction level consists of a constant number of bulk operations:

  1. sort records by successor identifier to attach each successor’s random bit;
  2. mark the independent set and emit restoration records;
  3. join selected nodes with their predecessors;
  4. rewrite the retained predecessor’s successor and weight;
  5. after recursion, join restoration records with successor ranks.

Each operation is a scan, external sort, or merge join, so a level on $n$ records costs $O(\operatorname{Sort}(n))$ I/Os. The expected recurrences are

$$ W(N)\le W(3N/4+O(1))+O(N)=O(N) $$ for ordinary work and $$ Q(N)\le Q(3N/4+O(1)) +O(\operatorname{Sort}(N)) =O(\operatorname{Sort}(N)) $$

for I/O. The sorting costs decrease geometrically with the contracted input sizes; they are not paid on the original $N$ records for every recursion level.

This result is expected because the contraction size is random. The random bits must come from a generator suitable for randomized algorithms, and a production pipeline should make the seed reproducible for debugging.

#Why It Is a Primitive

Many external-memory graph algorithms first express an irregular structure as linked records and then rank or prefix-sum that list. For a tree Euler tour, represent each traversal of a directed edge as one list item, link each item to the next traversal, break the resulting cycle at a chosen root position, and rank the list. The ranks give the tour order without chasing tree pointers in that order.

Weighted ranking also supplies suffix sums. Prefix positions follow from the total weight and a node’s suffix rank once the edge convention is fixed. Similar contraction ideas underlie tree contraction and parallel expression evaluation.

The randomized list-ranking primitive is used in the original work on external-memory graph algorithms. Its broader lesson is useful on its own: when pointer order is hostile to storage order, replace pointer chasing with sorting and joining on stable identifiers.
