Extended Euclidean Algorithm

The ordinary Euclidean algorithm answers a yes-or-no question about modular division: an integer $a$ has an inverse modulo $m$ exactly when $\gcd(a,m)=1$. The extended algorithm also constructs that inverse.

Its output is a triple $(g,x,y)$ satisfying Bézout’s identity:

$$ g=\gcd(a,b)=ax+by. $$ When $b=m$ and $g=1$, reducing the identity modulo $m$ erases the second term: $$ ax+my=1 \quad\Longrightarrow\quad ax\equiv1\pmod m. $$

Thus $x$ is the inverse of $a$ modulo $m$.

#Recovering the Coefficients

Euclid’s algorithm repeatedly uses

$$ \gcd(a,b)=\gcd(b,a\bmod b). $$ Suppose a recursive call has already found coefficients $x^\prime$ and $y^\prime$ such that $$ bx^\prime+(a\bmod b)y^\prime=g. $$ Substitute $$ a\bmod b=a-\left\lfloor\frac ab\right\rfloor b $$ and collect the coefficients of $a$ and $b$: $$ \begin{aligned} g &=bx^\prime+\left(a-\left\lfloor\frac ab\right\rfloor b\right)y^\prime\\ &=a\underbrace{y^\prime}_x +b\underbrace{\left(x^\prime-\left\lfloor\frac ab\right\rfloor y^\prime\right)}_y. \end{aligned} $$ So the return step is just $$ x=y^\prime,\qquad y=x^\prime-\left\lfloor\frac ab\right\rfloor y^\prime. $$

At the base case $b=0$, we have $a=a\cdot1+0\cdot0$.

#A Checked Implementation

The coefficients may be negative even when both inputs are unsigned. They can also require wider intermediate products than either input. GCC and Clang provide a signed 128-bit extension that is convenient for word-sized arithmetic:

#include <cstdint>
#include <optional>

struct bezout_result {
    uint64_t gcd;
    __int128 x;
    __int128 y;
};

bezout_result extended_gcd(uint64_t a, uint64_t b) {
    if (b == 0)
        return {a, 1, 0};

    auto next = extended_gcd(b, a % b);
    return {
        next.gcd,
        next.y,
        next.x - __int128(a / b) * next.y
    };
}

std::optional<uint64_t> inverse_mod(uint64_t a, uint64_t m) {
    if (m < 2)
        return std::nullopt;

    auto r = extended_gcd(a % m, m);
    if (r.gcd != 1)
        return std::nullopt;

    __int128 x = r.x % __int128(m);
    if (x < 0)
        x += m;
    return uint64_t(x);
}

Returning optional matters. Silently returning a coefficient when the gcd is not one turns an impossible division into a plausible-looking wrong residue. The normalization also uses % m, rather than adding $m$ once, because a generic Bézout coefficient is not part of an interface contract promising the range $(-m,m)$.

For portability beyond compilers with __int128, use a multiprecision coefficient type or establish input bounds that make a signed machine type safe.

#An Iterative Form

The recursion merely walks Euclid’s remainder sequence forward and substitutes coefficients while returning. We can carry two neighboring coefficient pairs directly:

bezout_result extended_gcd_iterative(uint64_t a, uint64_t b) {
    uint64_t old_r = a, r = b;
    __int128 old_x = 1, x = 0;
    __int128 old_y = 0, y = 1;

    while (r != 0) {
        uint64_t q = old_r / r;

        uint64_t next_r = old_r % r;
        old_r = r;
        r = next_r;

        __int128 next_x = old_x - __int128(q) * x;
        old_x = x;
        x = next_x;

        __int128 next_y = old_y - __int128(q) * y;
        old_y = y;
        y = next_y;
    }

    return {old_r, old_x, old_y};
}

At every iteration, the invariants are

$$ \mathtt{old\_r}=a\cdot\mathtt{old\_x}+b\cdot\mathtt{old\_y} $$ and $$ \mathtt{r}=a\cdot\mathtt{x}+b\cdot\mathtt{y}. $$

The quotient update applies the same operation to the remainders and their coefficient vectors, so the invariants survive until r becomes zero.

Both forms take $O(\log\min(a,b))$ divisions. The iterative version removes call overhead, but integer division remains the main cost; whether the difference matters depends on the surrounding computation.

#Beyond Inverses

Bézout coefficients solve the linear Diophantine equation

$$ au+bv=c. $$ A solution exists exactly when $\gcd(a,b)$ divides $c$. Multiplying the coefficients for the gcd by $c/g$ gives one solution, and all others follow by moving along $$ u=u_0+k\frac bg, \qquad v=v_0-k\frac ag. $$ The same construction is a building block for the Chinese remainder theorem and for Montgomery multiplication, where we need an inverse modulo a power of two. The algorithm is small, but its real output is not the gcd—it is an explicit certificate explaining how the gcd is assembled from the inputs.
