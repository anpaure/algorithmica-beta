Montgomery Multiplication

Reducing one product modulo $n$ is a division problem. Reducing a thousand products by the same $n$ is a representation problem.

Montgomery multiplication changes the representation of every residue so that reduction uses the inexpensive operations modulo a power of two. Entering and leaving the representation has a cost, so the method is useful for chains of products—modular exponentiation is the standard example—not for one isolated %.

#Montgomery Space

Choose a radix $R=2^w$ larger than an odd modulus $n$. The oddness condition is essential: it makes $\gcd(n,R)=1$, so $R$ has an inverse modulo $n$.

Represent a residue $x$ by

$$ \bar x=xR\bmod n. $$ Addition works as usual because $$ \bar x+\bar y\equiv(x+y)R\pmod n. $$ Ordinary multiplication introduces one factor of $R$ too many: $$ \bar x\bar y\equiv xyR^2\pmod n. $$ To obtain the representation of $xy$, we need a reduction operation $$ \operatorname{REDC}(T)=TR^{-1}\bmod n. $$ Then $$ \operatorname{REDC}(\bar x\bar y) \equiv xyR\pmod n, $$

which is exactly $\overline{xy}$.

#Making the Low Word Vanish

Precompute

$$ n^\prime=-n^{-1}\bmod R. $$ For an input $0\le T<nR$, calculate $$ q=(T\bmod R)n^\prime\bmod R. $$ The low $w$ bits of $T+qn$ are zero: $$ T+qn \equiv T+T(-n^{-1})n \equiv0\pmod R. $$ Division by $R$ is therefore exact, and because $R$ is a power of two, it is just a shift: $$ t=\frac{T+qn}{R}. $$ Modulo $n$, the added term disappears, so $$ t\equiv TR^{-1}\pmod n. $$ The range is small as well. Since $T<nR$ and $q<R$, $$ 0\le t<2n. $$

At most one subtraction is needed to obtain the canonical residue in $[0,n)$.

The trick is worth pausing over. We do not approximate the quotient. We deliberately add a multiple of $n$ whose low word cancels the low word of the input, making an exact division by the machine radix possible.

#A 32-Bit Implementation

The following implementation uses $R=2^{32}$. Restricting $n<2^{31}$ keeps T + q*n from overflowing 64 bits for products of reduced residues. A wider temporary can remove this restriction.

#include <cstdint>
#include <stdexcept>

class Montgomery32 {
    uint32_t n;
    uint32_t n_prime; // -n^{-1} modulo 2^32
    uint32_t r2;      // R^2 modulo n

public:
    explicit Montgomery32(uint32_t modulus) : n(modulus) {
        if (n <= 1 || n >= (uint32_t(1) << 31) || (n & 1) == 0)
            throw std::invalid_argument("modulus must be odd and in (1, 2^31)");

        // Start with the inverse modulo 2. Each Newton step doubles
        // the number of correct low bits: x <- x(2 - n*x).
        uint32_t inverse = 1;
        for (int i = 0; i < 5; ++i)
            inverse *= 2 - n * inverse;
        n_prime = 0 - inverse;

        uint64_t r = (uint64_t(1) << 32) % n;
        r2 = uint32_t(r * r % n);
    }

    uint32_t reduce(uint64_t T) const {
        // Precondition for this implementation: T < n^2.
        uint32_t q = uint32_t(T) * n_prime;
        uint64_t t = (T + uint64_t(q) * n) >> 32;
        return uint32_t(t >= n ? t - n : t);
    }

    uint32_t transform(uint32_t x) const {
        // REDC(x * R^2) = x * R.
        return reduce(uint64_t(x % n) * r2);
    }

    uint32_t canonical(uint32_t x) const {
        // Precondition: x is a Montgomery representative in [0, n).
        // If x = a * R modulo n, REDC(x) = a modulo n.
        return reduce(x);
    }

    uint32_t multiply(uint32_t x, uint32_t y) const {
        // x and y are canonical Montgomery representatives in [0, n).
        return reduce(uint64_t(x) * y);
    }

    uint32_t one() const {
        return transform(1);
    }
};

The type deliberately distinguishes transform from canonical: the former enters Montgomery space, while the latter leaves it. Applying ordinary % n to a Montgomery representative does not leave the representation—it is already a residue modulo $n$, just one encoding a different value.

#Computing the Inverse of the Modulus

The constructor uses a Newton-style lift. If $x$ is an inverse of odd $n$ modulo $2^k$, write $nx=1+c2^k$. Then

$$ \begin{aligned} n x(2-nx) &=(1+c2^k)(1-c2^k)\\ &=1-c^2 2^{2k}\\ &\equiv1\pmod{2^{2k}}. \end{aligned} $$

Thus x *= 2 - n*x doubles the number of correct low bits. Every odd number is congruent to one modulo 2, so x=1 is a valid starting point. Five doublings take us from 1 correct bit to all 32 bits—not 32 iterations.

Unsigned overflow in this loop is intentional: C++ defines it modulo $2^{32}$, exactly the arithmetic we need. The final negation produces $n^\prime=-n^{-1}$ rather than $n^{-1}$; this sign matches the T + q*n form of REDC. An implementation using T - q*n would use the opposite convention. Mixing the two is a common and remarkably quiet bug.

#Exponentiation in Montgomery Space

Values should cross the representation boundary only once:

uint32_t pow_mod(uint32_t a, uint64_t exponent,
                 const Montgomery32& space) {
    uint32_t base = space.transform(a);
    uint32_t result = space.one();

    while (exponent != 0) {
        if (exponent & 1)
            result = space.multiply(result, base);
        exponent >>= 1;
        if (exponent != 0)
            base = space.multiply(base, base);
    }

    return space.canonical(result);
}

The loop contains multiplication, shifts, and a conditional subtraction, but no division by $n$. The divisions used to construct r2 are paid once per modulus. As written, transform also evaluates x % n so that it accepts an arbitrary 32-bit input; that conversion cost is paid once per value before a multiplication chain. An interface requiring x < n could omit the normalization. When the modulus is a compile-time constant, compiler-generated reciprocal reduction may already be excellent; when the modulus changes frequently, Montgomery setup may never pay for itself. Benchmark the whole workload.

#Bounds, Limbs, and Constant Time

Production implementations vary in three important ways.

First, some keep a lazy result in $[0,2n)$ and postpone the final subtraction. This can shorten a dependency chain, but every following operation must honor the wider range. A bound proved for normalized operands cannot simply be reused.

Second, 64-bit and multiprecision variants use instructions that return the high and low halves of a product. Multiword REDC cancels one limb at a time and is the basis of many large-integer modular exponentiation routines.

Third, cryptographic code must consider timing and other side channels. A source-level ternary operator is not a guarantee of constant-time machine code, and a fast educational implementation is not a replacement for a reviewed cryptographic library. Use vetted primitives when secrets are involved.

Montgomery multiplication is a particularly clean performance transformation: the mathematical operation stays the same, but choosing a representation aligned with the hardware turns a hard division into low-word cancellation and a shift.
