Masking and Blending

SIMD applies one instruction to every lane, so data-dependent control flow is usually represented as data. A comparison produces a mask, and later operations use that mask to keep, clear, or select lanes.

With AVX2 integer comparisons, a true 32-bit lane contains 0xffffffff and a false lane contains zero. AVX-512 adds dedicated k mask registers and masked forms of many instructions, but the exact form still depends on AVX-512 subsets and runtime support.

#Predication

Suppose the input contains nonnegative integers and we want the sum of values below 50. The scalar branch can be written as predication:

if (data[i] < 50)
    sum += data[i];

sum += data[i] < 50 ? data[i] : 0;

AVX2 can clear rejected lanes with one comparison and one bitwise AND:

std::int32_t sum_below_50(const std::int32_t *data, std::size_t n) {
    const __m256i limit = _mm256_set1_epi32(50);
    __m256i sum = _mm256_setzero_si256();
    std::size_t i = 0;

    for (; i + 8 <= n; i += 8) {
        const __m256i x = _mm256_loadu_si256(
            reinterpret_cast<const __m256i *>(data + i));
        const __m256i selected = _mm256_and_si256(
            x, _mm256_cmpgt_epi32(limit, x));
        sum = _mm256_add_epi32(sum, selected);
    }

    std::int32_t result = static_cast<std::int32_t>(horizontal_sum(sum));
    for (; i < n; ++i)
        if (data[i] < 50)
            result += data[i];
    return result;
}

This example uses the horizontal_sum helper from the previous section and assumes the selected values and total fit in int32_t; otherwise use a widened reduction. _mm256_blendv_epi8(zero, x, mask) expresses the same choice when the comparison mask contains all-zero/all-one lanes, but an AND is simpler when one alternative is zero. Their relative throughput is microarchitecture-specific.

Other mask interfaces include _mm256_blend_epi32, whose selection mask is an immediate, and _mm256_maskload_epi32/_mm256_maskstore_epi32, which suppress memory access for masked-off 32-bit lanes. Masked-off loads become zero; these instructions are not general bounds checks, and every active lane must still address a valid object.

#Finding the First Match

To find a 32-bit value, compare eight elements and compress the sign bit of every all-one/all-zero lane into an 8-bit scalar mask with _mm256_movemask_ps. The first set bit identifies the first match.

Processing four vectors per iteration amortizes the loop test while preserving order:

std::uint32_t lane_mask(__m256i mask) {
    return static_cast<std::uint32_t>(
        _mm256_movemask_ps(_mm256_castsi256_ps(mask)));
}

std::ptrdiff_t find_avx2(const std::int32_t *data, std::size_t n,
                         std::int32_t needle) {
    const __m256i target = _mm256_set1_epi32(needle);
    std::size_t i = 0;

    for (; i + 32 <= n; i += 32) {
        const __m256i m0 = _mm256_cmpeq_epi32(
            target, _mm256_loadu_si256(
                reinterpret_cast<const __m256i *>(data + i)));
        const __m256i m1 = _mm256_cmpeq_epi32(
            target, _mm256_loadu_si256(
                reinterpret_cast<const __m256i *>(data + i + 8)));
        const __m256i m2 = _mm256_cmpeq_epi32(
            target, _mm256_loadu_si256(
                reinterpret_cast<const __m256i *>(data + i + 16)));
        const __m256i m3 = _mm256_cmpeq_epi32(
            target, _mm256_loadu_si256(
                reinterpret_cast<const __m256i *>(data + i + 24)));

        const __m256i any = _mm256_or_si256(
            _mm256_or_si256(m0, m1), _mm256_or_si256(m2, m3));
        if (!_mm256_testz_si256(any, any)) {
            const std::uint32_t mask = lane_mask(m0)
                                     | (lane_mask(m1) << 8)
                                     | (lane_mask(m2) << 16)
                                     | (lane_mask(m3) << 24);
            return static_cast<std::ptrdiff_t>(i + std::countr_zero(mask));
        }
    }

    for (; i + 8 <= n; i += 8) {
        const __m256i match = _mm256_cmpeq_epi32(
            target, _mm256_loadu_si256(
                reinterpret_cast<const __m256i *>(data + i)));
        const std::uint32_t mask = lane_mask(match);
        if (mask != 0)
            return static_cast<std::ptrdiff_t>(i + std::countr_zero(mask));
    }

    for (; i < n; ++i)
        if (data[i] == needle)
            return static_cast<std::ptrdiff_t>(i);
    return -1;
}

std::countr_zero is called only for a nonzero mask. Every vector is guarded by an in-bounds condition, so the function works for empty inputs and every tail length without padding. The four-vector grouping helped the historical Zen 2 benchmark, whose front end and mask instructions limited shorter loops; another processor may prefer one or two vectors.

#Counting 32-Bit Values

A comparison mask already represents true as -1. The straightforward version ANDs it with a vector of ones and accumulates positive counts. First split that accumulator into two independent chains to expose instruction-level parallelism; only then consider eliminating the AND by accumulating the -1 masks themselves.

The final form below does both. It periodically widens to a scalar total so a 32-bit lane cannot overflow:

std::uint64_t count_equal_avx2(const std::int32_t *data, std::size_t n,
                               std::int32_t needle) {
    constexpr std::size_t chunk = 1u << 20; // divisible by 16
    const __m256i target = _mm256_set1_epi32(needle);
    std::uint64_t total = 0;
    std::size_t i = 0;

    while (i + 16 <= n) {
        const std::size_t vector_elements = (n - i) & ~std::size_t{15};
        const std::size_t block = std::min(vector_elements, chunk);
        const std::size_t end = i + block;
        __m256i count0 = _mm256_setzero_si256();
        __m256i count1 = _mm256_setzero_si256();

        for (; i < end; i += 16) {
            const __m256i x0 = _mm256_loadu_si256(
                reinterpret_cast<const __m256i *>(data + i));
            const __m256i x1 = _mm256_loadu_si256(
                reinterpret_cast<const __m256i *>(data + i + 8));
            count0 = _mm256_add_epi32(
                count0, _mm256_cmpeq_epi32(x0, target));
            count1 = _mm256_add_epi32(
                count1, _mm256_cmpeq_epi32(x1, target));
        }

        alignas(32) std::array<std::int32_t, 8> lane{};
        _mm256_store_si256(
            reinterpret_cast<__m256i *>(lane.data()),
            _mm256_add_epi32(count0, count1));
        for (std::int32_t x : lane)
            total += static_cast<std::uint64_t>(-static_cast<std::int64_t>(x));
    }

    for (; i < n; ++i)
        total += data[i] == needle;
    return total;
}

Each lane is a small nonpositive number inside a chunk, so negating it in 64-bit scalar arithmetic is safe. Without chunking, a sufficiently large array would wrap the packed counters even though the final return type is wider.

#Counting Bytes Without Overflow

For byte inputs, _mm256_cmpeq_epi8 produces 32 byte masks. ANDing with byte-wise ones makes each lane gain at most 1 per vector, so one 8-bit accumulator can process 255 vectors before it must be widened. Two independent accumulators can process 510 vectors because each receives at most 255 updates:

std::uint64_t count_equal_bytes_avx2(const std::uint8_t *data,
                                     std::size_t n,
                                     std::uint8_t needle) {
    const __m256i target = _mm256_set1_epi8(
        std::bit_cast<std::int8_t>(needle));
    const __m256i one = _mm256_set1_epi8(1);
    const __m256i zero = _mm256_setzero_si256();
    std::uint64_t total = 0;
    std::size_t i = 0;

    while (i + 32 <= n) {
        const std::size_t blocks = std::min<std::size_t>(510, (n - i) / 32);
        __m256i count0 = zero;
        __m256i count1 = zero;
        std::size_t b = 0;

        for (; b + 1 < blocks; b += 2) {
            const __m256i x0 = _mm256_loadu_si256(
                reinterpret_cast<const __m256i *>(data + i + 32 * b));
            const __m256i x1 = _mm256_loadu_si256(
                reinterpret_cast<const __m256i *>(data + i + 32 * (b + 1)));
            count0 = _mm256_add_epi8(
                count0, _mm256_and_si256(_mm256_cmpeq_epi8(x0, target), one));
            count1 = _mm256_add_epi8(
                count1, _mm256_and_si256(_mm256_cmpeq_epi8(x1, target), one));
        }
        if (b < blocks) {
            const __m256i x = _mm256_loadu_si256(
                reinterpret_cast<const __m256i *>(data + i + 32 * b));
            count0 = _mm256_add_epi8(
                count0, _mm256_and_si256(_mm256_cmpeq_epi8(x, target), one));
        }

        const __m256i groups = _mm256_add_epi64(
            _mm256_sad_epu8(count0, zero),
            _mm256_sad_epu8(count1, zero));
        alignas(32) std::array<std::uint64_t, 4> partial{};
        _mm256_store_si256(
            reinterpret_cast<__m256i *>(partial.data()), groups);
        total += std::accumulate(partial.begin(), partial.end(), std::uint64_t{0});
        i += 32 * blocks;
    }

    for (; i < n; ++i)
        total += data[i] == needle;
    return total;
}

The overflow bound depends on the largest per-vector increment. Equality contributes at most 1 to each byte lane, hence 255 vectors per accumulator. The nibble-popcount kernel in the next section contributes as much as 8, hence $\lfloor255/8\rfloor=31$ vectors—not 15. Stating the lane increment is more reliable than dividing 255 by the number of elements in an unrelated vector type.
