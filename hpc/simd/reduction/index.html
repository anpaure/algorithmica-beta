Algorithmica βReductions

Reductions

A reduction combines a range into one value: sum, minimum, maximum, bitwise OR, and XOR are common examples. Parallel grouping needs an associative operation and an identity. Commutativity is convenient but not always required if the implementation preserves operand order.

Floating-point addition is not mathematically associative because every intermediate result is rounded. A vectorized sum may therefore differ in its low bits from a left-to-right scalar sum. Compilers honor or relax that constraint according to the language mode and floating-point flags.

For an exact integer example, use unsigned addition, whose modulo-$2^{32}$ wrap is defined:

std::uint32_t sum_scalar(const std::uint32_t *a, std::size_t n) {
    std::uint32_t sum = 0;
    for (std::size_t i = 0; i < n; ++i)
        sum += a[i];
    return sum;
}

#Vector Accumulators

One 256-bit integer accumulator holds eight partial sums. Each vector addition updates them independently:

std::uint32_t horizontal_sum(__m256i value) {
    __m128i sum = _mm_add_epi32(
        _mm256_castsi256_si128(value),
        _mm256_extracti128_si256(value, 1));
    sum = _mm_add_epi32(sum, _mm_srli_si128(sum, 8));
    sum = _mm_add_epi32(sum, _mm_srli_si128(sum, 4));
    return static_cast<std::uint32_t>(_mm_cvtsi128_si32(sum));
}

std::uint32_t sum_avx2(const std::uint32_t *a, std::size_t n) {
    __m256i sum = _mm256_setzero_si256();
    std::size_t i = 0;

    for (; i + 8 <= n; i += 8) {
        const __m256i x = _mm256_loadu_si256(
            reinterpret_cast<const __m256i *>(a + i));
        sum = _mm256_add_epi32(sum, x);
    }

    std::uint32_t result = horizontal_sum(sum);
    for (; i < n; ++i)
        result += a[i];
    return result;
}

The pointer remains a pointer to scalar elements, so the tail indexes the right type. The loop condition proves every vector load has eight accessible elements. No alignment or padding is assumed.

For a mathematical signed sum that must not wrap, widen before accumulation. AVX2 can widen four 32-bit integers at a time to 64-bit lanes with _mm256_cvtepi32_epi64; whether that is worthwhile depends on the required range and memory bottleneck.

#Instruction-Level Parallelism

One vector accumulator forms a dependency chain. If vector addition has latency $L$ cycles but the core can start more than one addition per cycle, independent accumulators can cover that latency:

std::uint32_t sum_avx2_two_accumulators(const std::uint32_t *a,
                                        std::size_t n) {
    __m256i sum0 = _mm256_setzero_si256();
    __m256i sum1 = _mm256_setzero_si256();
    std::size_t i = 0;

    for (; i + 16 <= n; i += 16) {
        const __m256i x0 = _mm256_loadu_si256(
            reinterpret_cast<const __m256i *>(a + i));
        const __m256i x1 = _mm256_loadu_si256(
            reinterpret_cast<const __m256i *>(a + i + 8));
        sum0 = _mm256_add_epi32(sum0, x0);
        sum1 = _mm256_add_epi32(sum1, x1);
    }

    if (i + 8 <= n) {
        sum0 = _mm256_add_epi32(
            sum0,
            _mm256_loadu_si256(reinterpret_cast<const __m256i *>(a + i)));
        i += 8;
    }

    std::uint32_t result = horizontal_sum(_mm256_add_epi32(sum0, sum1));
    for (; i < n; ++i)
        result += a[i];
    return result;
}

The second vector accumulator is not justified merely by “two execution ports.” The useful count depends on latency, reciprocal throughput, load bandwidth, unrolling, and register pressure. Once memory bandwidth dominates, extra accumulators only add bookkeeping. Compilers routinely perform this transformation themselves for simple integer reductions.

#Horizontal Reduction

Combining lanes is called a horizontal reduction. It is a tree rather than one general AVX2 instruction. The implementation above first adds the 128-bit halves, then uses byte shifts and packed adds until the total reaches lane zero.

Special-purpose horizontal instructions exist. SSE4.1 _mm_minpos_epu16, for example, returns the minimum and index among eight unsigned 16-bit lanes. _mm256_sad_epu8 efficiently sums groups of unsigned bytes. Most reductions still need several steps, so reduce once after a long vector loop rather than extracting a scalar on every iteration.
