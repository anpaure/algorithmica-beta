In-Register Shuffles

Masks select lanes without changing their order. Shuffles go further: they copy or rearrange elements inside a vector. No single x86 instruction implements every possible permutation at every element width. Some shuffles use an immediate pattern, some take vector indices, and many AVX2 byte shuffles operate independently in two 128-bit lanes.

Two examples show why these details matter: table-driven population count and stable filtering.

#Scalar Population Count

Population count, or Hamming weight, is the number of one bits. C++20 exposes it as std::popcount; GCC and Clang also provide built-ins:

std::uint64_t popcount_words(const std::uint64_t *data, std::size_t n) {
    std::uint64_t total = 0;
    for (std::size_t i = 0; i < n; ++i)
        total += std::popcount(data[i]);
    return total;
}

When compiled with the x86 POPCNT feature, this usually becomes one scalar popcnt per word plus accumulation. POPCNT has its own CPUID bit; it is not “an SSE4 instruction,” even though it appeared in processors of a similar era. A dispatched implementation should test popcnt separately.

Without POPCNT, a byte lookup table is a useful intermediate design:

constexpr std::array<std::uint8_t, 256> make_popcount_table() {
    std::array<std::uint8_t, 256> table{};
    for (std::size_t value = 0; value < table.size(); ++value)
        table[value] = static_cast<std::uint8_t>(
            std::popcount(static_cast<unsigned>(value)));
    return table;
}

inline constexpr auto byte_popcount = make_popcount_table();

std::uint64_t popcount_bytes_table(const std::uint8_t *data,
                                   std::size_t bytes) {
    std::uint64_t total = 0;
    for (std::size_t i = 0; i < bytes; ++i)
        total += byte_popcount[data[i]];
    return total;
}

This avoids signed right shifts and pointer punning. It also exposes the next optimization: put a smaller table in a vector register.

#Nibble Lookup with pshufb

SSSE3 introduced the 128-bit pshufb byte shuffle. AVX2 _mm256_shuffle_epi8 applies the same 16-entry lookup independently to the low and high 128-bit lanes, so a 16-byte table must be repeated:

const __m256i lookup = _mm256_setr_epi8(
    0, 1, 1, 2, 1, 2, 2, 3, 1, 2, 2, 3, 2, 3, 3, 4,
    0, 1, 1, 2, 1, 2, 2, 3, 1, 2, 2, 3, 2, 3, 3, 4);

Split every byte into low and high nibbles, look up both counts, and add them. A byte lane can then increase by at most 8 per vector, so at most

$$ \left\lfloor\frac{255}{8}\right\rfloor=31 $$

vectors may accumulate before widening. The old 15-iteration bound was both arithmetically wrong and tied to an invalid loop shape.

std::uint64_t popcount_avx2(const std::uint8_t *data, std::size_t bytes) {
    const __m256i lookup = _mm256_setr_epi8(
        0, 1, 1, 2, 1, 2, 2, 3, 1, 2, 2, 3, 2, 3, 3, 4,
        0, 1, 1, 2, 1, 2, 2, 3, 1, 2, 2, 3, 2, 3, 3, 4);
    const __m256i low_nibble = _mm256_set1_epi8(0x0f);
    const __m256i zero = _mm256_setzero_si256();
    __m256i wide_total = zero;
    std::size_t i = 0;

    while (i + 32 <= bytes) {
        const std::size_t blocks = std::min<std::size_t>(31, (bytes - i) / 32);
        __m256i byte_count = zero;

        for (std::size_t block = 0; block < blocks; ++block) {
            const __m256i x = _mm256_loadu_si256(
                reinterpret_cast<const __m256i *>(data + i + 32 * block));
            const __m256i low = _mm256_and_si256(x, low_nibble);
            const __m256i high = _mm256_and_si256(
                _mm256_srli_epi16(x, 4), low_nibble);
            byte_count = _mm256_add_epi8(
                byte_count, _mm256_shuffle_epi8(lookup, low));
            byte_count = _mm256_add_epi8(
                byte_count, _mm256_shuffle_epi8(lookup, high));
        }

        wide_total = _mm256_add_epi64(
            wide_total, _mm256_sad_epu8(byte_count, zero));
        i += 32 * blocks;
    }

    alignas(32) std::array<std::uint64_t, 4> partial{};
    _mm256_store_si256(
        reinterpret_cast<__m256i *>(partial.data()), wide_total);
    std::uint64_t total = std::accumulate(
        partial.begin(), partial.end(), std::uint64_t{0});

    for (; i < bytes; ++i)
        total += std::popcount(static_cast<unsigned>(data[i]));
    return total;
}

The loop advances in bytes, loads exactly 32 bytes per vector, and handles every remaining byte scalarly. It requires AVX2 at compile time and runtime; the equivalent 128-bit lookup only requires SSSE3. The historical Zen 2 implementation processed about 30 input bytes per cycle, but modern AVX-512 VPOPCNTDQ or BITALG implementations and other processors have different best kernels.

Wojciech Muła’s SIMD popcount repository and the associated Harley–Seal paper cover several stronger algorithms.

#Stable Filtering with a Permutation Table

A stable filter writes values satisfying a predicate in their original order:

std::size_t filter_scalar(const std::int32_t *input, std::size_t n,
                          std::int32_t threshold, std::int32_t *output) {
    std::size_t written = 0;
    for (std::size_t i = 0; i < n; ++i)
        if (input[i] < threshold)
            output[written++] = input[i];
    return written;
}

For eight AVX2 lanes there are only 256 possible comparison masks. Precompute, for each mask, the indices of selected lanes followed by harmless zeros:

struct alignas(32) PermutationTable {
    std::array<std::array<std::int32_t, 8>, 256> row{};

    constexpr PermutationTable() {
        for (std::size_t mask = 0; mask < row.size(); ++mask) {
            std::size_t out = 0;
            for (std::int32_t lane = 0; lane < 8; ++lane)
                if (mask & (std::size_t{1} << lane))
                    row[mask][out++] = lane;
        }
    }
};

inline constexpr PermutationTable permutation{};

_mm256_permutevar8x32_epi32 copies lanes according to eight vector indices. Duplicates are allowed, so “permute” is broader here than a mathematical permutation:

std::size_t filter_avx2(const std::int32_t *input, std::size_t n,
                        std::int32_t threshold, std::int32_t *output) {
    const __m256i limit = _mm256_set1_epi32(threshold);
    std::size_t written = 0;
    std::size_t i = 0;

    for (; i + 8 <= n; i += 8) {
        __m256i value = _mm256_loadu_si256(
            reinterpret_cast<const __m256i *>(input + i));
        const __m256i selected = _mm256_cmpgt_epi32(limit, value);
        const unsigned mask = static_cast<unsigned>(
            _mm256_movemask_ps(_mm256_castsi256_ps(selected)));
        const __m256i order = _mm256_load_si256(
            reinterpret_cast<const __m256i *>(permutation.row[mask].data()));
        value = _mm256_permutevar8x32_epi32(value, order);
        _mm256_storeu_si256(
            reinterpret_cast<__m256i *>(output + written), value);
        written += std::popcount(mask);
    }

    for (; i < n; ++i)
        if (input[i] < threshold)
            output[written++] = input[i];
    return written;
}

The output allocation must contain at least n elements. That is enough for every full store: before the block at i, written <= i, hence the eight-lane store ends no later than i + 7 < n. The scalar tail avoids an input overread and needs no extra padding. The unused lanes written after the valid prefix are overwritten by a later block or remain outside the returned prefix.

The original Zen 2 result was roughly 6–7 times faster for its random predicate, while predictable scalar branches narrowed the gap. Port pressure and shuffle throughput are processor-specific, so retain the result as historical evidence rather than predicting another x86 core from it.

AVX-512F provides compress instructions and mask registers that remove the 256-row table. A compress-store writes only selected lanes contiguously, and an AVX-512 masked tail can avoid scalar cleanup. It still requires runtime dispatch, sufficient output capacity, and the precise AVX-512 features used by that implementation.
