Argmin with SIMD

Finding the minimum of an array is a reduction. Finding where that minimum occurs is a reduction carrying luggage: every candidate value brings an index with it.

That extra word changes the optimization problem. A vector minimum combines eight 32-bit values with one AVX2 instruction, but a vector argmin must also decide which indices survive, define what happens on ties, and reduce eight (value, index) pairs at the end. The fastest-looking loop is often the one that quietly gets one of those details wrong.

We will use a precise contract and then develop two implementations: a scalar oracle and a blocked SIMD algorithm that reads the array once plus one small block.

#The Contract

For an array $a$ of length $n>0$, define

$$ \operatorname{argmin}(a)=\min\{i\mid a_i=\min_j a_j\}. $$

The outer min makes ties explicit: return the first occurrence. For an empty array there is no such index, so the interface returns std::nullopt.

#include <cstddef>
#include <cstdint>
#include <optional>
#include <span>

std::optional<std::size_t>
argmin_scalar(std::span<const std::int32_t> values) {
    if (values.empty())
        return std::nullopt;

    std::size_t best = 0;
    for (std::size_t i = 1; i < values.size(); ++i)
        if (values[i] < values[best])
            best = i;
    return best;
}

The comparison is strict. Changing < to <= changes the result to the last minimum. Initializing the best value to INT_MAX without separately initializing an index also fails for an array consisting entirely of INT_MAX.

The standard-library equivalent is compact and has the same first-tie rule:

#include <algorithm>

std::optional<std::size_t>
argmin_standard(std::span<const std::int32_t> values) {
    if (values.empty())
        return std::nullopt;
    auto it = std::min_element(values.begin(), values.end());
    return static_cast<std::size_t>(it - values.begin());
}

Whether either loop vectorizes is a compiler and target question. std::min_element is not inherently slow, and one old library/compiler result is not a reason to avoid it. Inspect the generated code and benchmark the exact toolchain.

#Carrying Indices in Vectors

The direct SIMD translation keeps eight partial minima and eight corresponding indices. For a vector x and current minima m, form the signed comparison mask

$$ q=(xThis is correct when the comparison is strict and the final horizontal reduction compares (value, index) pairs lexicographically. It also has some unglamorous engineering requirements:

  • _mm256_load_si256 requires a 32-byte-aligned address; ordinary arrays do not promise that alignment, so a general routine needs loadu or a proven aligned fast path;
  • a loop stepping by eight needs a scalar or masked tail;
  • 32-bit vector indices wrap when the array has more than $2^{32}$ elements;
  • the final reduction must prefer the lower index when two lanes contain the same value.

The value comparison, two blends, and index increment also create more work than a plain minimum. There is a simpler way to keep full-width std::size_t indices out of the vector loop altogether.

#Find a Block, Then an Index

Split the array into small blocks. Compute each block minimum with SIMD, keep the first block whose minimum strictly improves the global minimum, and finally scan only that block for the first matching value.

If the block size is $B$, the algorithm examines $n+B$ elements in the worst case. It has a useful invariant after processing blocks through $t$:

best_value is the minimum of the processed prefix, and best_block is the first block containing that value.

A strictly smaller block minimum replaces both. An equal one does not, so ties across blocks retain the earlier block. A forward scalar scan then resolves ties inside the chosen block.

Here is a complete AVX2 implementation for signed 32-bit integers. It accepts arbitrary lengths and unaligned data.

#include <algorithm>
#include <array>
#include <climits>
#include <cstddef>
#include <cstdint>
#include <immintrin.h>
#include <optional>
#include <span>

std::int32_t block_min_avx2(const std::int32_t *data,
                            std::size_t length) {
    // The public routine calls this only for nonempty blocks.
    __m256i minimum = _mm256_set1_epi32(INT_MAX);
    std::size_t i = 0;

    for (; length - i >= 8; i += 8) {
        const __m256i x = _mm256_loadu_si256(
            reinterpret_cast<const __m256i *>(data + i));
        minimum = _mm256_min_epi32(minimum, x);
    }

    alignas(32) std::array<std::int32_t, 8> lanes{};
    _mm256_store_si256(reinterpret_cast<__m256i *>(lanes.data()), minimum);

    std::int32_t result = INT_MAX;
    for (std::int32_t x : lanes)
        result = std::min(result, x);
    for (; i < length; ++i)
        result = std::min(result, data[i]);
    return result;
}

std::optional<std::size_t>
argmin_avx2(std::span<const std::int32_t> values) {
    if (values.empty())
        return std::nullopt;

    constexpr std::size_t block_size = 256;
    std::int32_t best_value = INT_MAX;
    std::size_t best_block = 0;
    std::size_t best_length = std::min(block_size, values.size());

    for (std::size_t base = 0; base < values.size(); base += block_size) {
        const std::size_t length =
            std::min(block_size, values.size() - base);
        const std::int32_t local =
            block_min_avx2(values.data() + base, length);

        if (local < best_value) {
            best_value = local;
            best_block = base;
            best_length = length;
        }
    }

    for (std::size_t i = 0; i < best_length; ++i)
        if (values[best_block + i] == best_value)
            return best_block + i;

    // Defensive fallback: the block minimum must occur in this block.
    return std::nullopt;
}

_mm256_loadu_si256 removes the caller-facing alignment precondition. The loop condition i + 8 <= length prevents an out-of-bounds vector read, and the scalar loop handles every remaining element. Since the outer loop computes its length with values.size() - base, the final partial block is no different from any other.

The INT_MAX initialization is safe here. If the first block contains only INT_MAX, the strict comparison does not update best_block; it already names that first block, and the final scan finds index zero. A later all-INT_MAX block cannot steal the tie.

This code must be compiled for AVX2 and called only on a processor that supports it. A portable binary normally keeps argmin_scalar as a baseline and selects an AVX2 function through compile-time targets or runtime feature dispatch. The dispatch belongs outside the hot loop.

#Why a Branch Can Be Fast—or Terrible

There is another attractive design. Compare each vector block with a broadcast global minimum, and enter a scalar slow path only if some lane may improve it. For independent values from a continuous distribution, the probability that element $i$ is a new record minimum is $1/(i+1)$, so the expected number of record updates is the harmonic number

$$ H_n=1+\frac12+\cdots+\frac1n=\log n+O(1). $$

On that distribution the slow branch is rare. On a decreasing array it is taken for every block. Duplicate-heavy, nearly sorted, adversarial, and correlated data fall somewhere else again. [[unlikely]] communicates a workload assumption to the compiler; it does not make the assumption true.

The blocked algorithm above avoids this distribution-dependent scalar slow path. It performs a horizontal reduction once per fixed block regardless of the order of the values. The block size still needs measurement: larger blocks reduce horizontal reductions but increase the final rescan and may interact differently with cache residency.

#One Pass Versus Two

Computing the global minimum first and then using a vectorized equality search is especially simple:

auto minimum = vector_min(values);
auto index = vector_find_first(values, minimum);

It is robust, but it reads between one and two arrays’ worth of data: the second pass stops early only when the first minimum occurs early. For a cache-resident array this may be competitive. For a large array, a mandatory second memory pass can cost more than the index bookkeeping it saved.

Blocking is a compromise. It reads the entire array once and revisits at most $B$ values. The extra work is bounded rather than dependent on where the first minimum happens.

#Historical Experiment

The original 2022 experiment used $2^{13}$ integers, a 2 GHz Zen 2 core, GCC 9.3, and only two input families: pseudo-random values and a decreasing sequence. Its table called the unit “GFLOPS,” although no floating-point operation is involved; the numbers are more accurately billions of elements examined per second.

These measurements preserve the useful shape of the experiment: a rare-path optimization can be spectacular on random data and collapse on decreasing data, while the blocked design is much steadier. They do not establish a universal 15-fold speedup. The compiler is old, the arrays fit in a small cache, the benchmark is noisy, and two distributions are not a workload study.

For new measurements, report elements per second and bytes per second, not FLOPS. Sweep length across cache boundaries; vary alignment and the position and multiplicity of the minimum; include increasing, decreasing, constant, random, and application traces; and retain the result so the optimizer cannot remove the scan.

#Differential Testing

The scalar routine is a convenient oracle. Before timing the AVX2 version, compare it for:

  • every length around vector and block boundaries: 0 through 17, 255 through 257, and 511 through 513;
  • every byte offset compatible with int32_t in an oversized allocation;
  • all-equal arrays and duplicate minima in different lanes and blocks;
  • increasing and decreasing arrays;
  • INT_MIN, INT_MAX, and mixtures of both;
  • random arrays over both a wide domain and a tiny duplicate-heavy domain.

For every nonempty input, verify both the value and the first-tie property:

auto expected = argmin_scalar(values);
auto actual = argmin_avx2(values);
assert(actual == expected);
assert(values[*actual] == *std::min_element(values.begin(), values.end()));

Run the suite with address and undefined-behavior sanitizers. A vector loop that is correct only for the old aligned, power-of-two benchmark will usually fail on the first offset or tail case.

Argmin illustrates why SIMD programming is less about replacing scalar operators with vector operators than about choosing the right representation. Carrying eight indices is possible; arranging the computation so indices remain scalar is often better.
