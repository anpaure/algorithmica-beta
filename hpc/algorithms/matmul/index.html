Matrix Multiplication

Matrix multiplication is where several modest optimizations learn to cooperate. Change the loop order and memory becomes sequential. Block the loops and cache lines are reused. Keep a tile of the result in registers and loads are reused. Apply SIMD and one instruction updates eight cells. None of these ideas is sufficient alone; together they separate a textbook triple loop from a BLAS kernel.

They also create plenty of places to cheat accidentally. Square-only code hides dimension errors. A microkernel that assumes multiples of 16 has no tail. Aligned loads turn an allocation choice into an undocumented precondition. Counting one fused multiply-add as one FLOP understates both measured throughput and machine peak by a factor of two.

We will begin with a complete rectangular contract, build a reference implementation, and then optimize it without losing the awkward cases.

#Dimensions and Storage

Let $A$ be $M\times K$ and $B$ be $K\times N$. Their product $C=AB$ is $M\times N$:

$$ C_{ij}=\sum_{p=0}^{K-1}A_{ip}B_{pj}. $$

All matrices below are row-major. Their leading dimensions lda, ldb, and ldc are row strides measured in elements, not bytes:

A(i,p) = a[i * lda + p]
B(p,j) = b[p * ldb + j]
C(i,j) = c[i * ldc + j]

A stride may exceed the logical width because rows are padded or are views into larger matrices. The operation overwrites the logical $M\times N$ region of C; it leaves row padding untouched. The spans for A, B, and C must not overlap. If aliasing is required, copy the overlapping input before calling the kernel.

Empty dimensions are well-defined. If $M=0$ or $N=0$, nothing is written. If $K=0$, every logical element of C is set to zero.

#Validate the View

Pointer arithmetic is part of correctness. Before entering a hot loop, verify both the stride and the last address a logical matrix may use.

#include <cstddef>
#include <limits>
#include <span>
#include <stdexcept>

std::size_t matrix_extent(std::size_t rows,
                          std::size_t columns,
                          std::size_t stride) {
    if (rows == 0 || columns == 0)
        return 0;
    if (stride < columns)
        throw std::invalid_argument("matrix stride is smaller than width");

    const std::size_t limit = std::numeric_limits<std::size_t>::max();
    if (rows - 1 > (limit - columns) / stride)
        throw std::length_error("matrix extent overflows size_t");
    return (rows - 1) * stride + columns;
}

void require_matrix(std::size_t available,
                    std::size_t rows,
                    std::size_t columns,
                    std::size_t stride) {
    if (matrix_extent(rows, columns, stride) > available)
        throw std::out_of_range("matrix span is too short");
}

The last logical row starts at (rows - 1) * stride; adding columns gives the one-past extent. Checking the multiplication before performing it prevents validation itself from overflowing.

#A Numerical Reference

The reference accumulates each dot product in double and rounds once when storing a float. Products of two binary32 values are exactly representable in binary64, and the wider accumulator is much more accurate than the optimized binary32 kernel. It is deliberately a correctness oracle, not a performance baseline.

#include <cmath>
#include <cstddef>
#include <span>

void matmul_reference(std::span<const float> a,
                      std::span<const float> b,
                      std::span<float> c,
                      std::size_t m,
                      std::size_t k,
                      std::size_t n,
                      std::size_t lda,
                      std::size_t ldb,
                      std::size_t ldc) {
    require_matrix(a.size(), m, k, lda);
    require_matrix(b.size(), k, n, ldb);
    require_matrix(c.size(), m, n, ldc);

    for (std::size_t i = 0; i < m; ++i) {
        for (std::size_t j = 0; j < n; ++j) {
            double sum = 0;
            for (std::size_t p = 0; p < k; ++p) {
                sum = std::fma(static_cast<double>(a[i * lda + p]),
                               static_cast<double>(b[p * ldb + j]),
                               sum);
            }
            c[i * ldc + j] = static_cast<float>(sum);
        }
    }
}

This also fixes a common initialization bug. A routine implementing C = A*B must overwrite or clear C; a loop containing only c[...] += ... instead implements C += A*B and depends on the caller’s previous contents.

#Counting Work Correctly

For $K>0$, each output dot product performs $K$ multiplications and $K-1$ additions. The exact count is

$$ MN(2K-1). $$ Performance reports conventionally use $2MNK$, counting one multiply and one add per inner update. A fused multiply-add performs both operations with one instruction and is therefore counted as two FLOPs per lane. For a runtime $t$ seconds, $$ \text{GFLOP/s}=\frac{2MNK}{10^9t}. $$

This convention slightly overcounts the first addition into zero but makes implementations and hardware peaks comparable. It must be stated; “operations” is otherwise ambiguous.

#Change the Loop Order

The literal i-j-p loop reads a row of A sequentially but walks down a column of row-major B with stride ldb. Transposing B makes both dot-product operands sequential, at the cost of allocation, copying, and a horizontal SIMD reduction.

There is another option. Exchange the inner loops:

zero C
for i in [0, M)
    for p in [0, K)
        alpha = A[i,p]
        for j in [0, N)
            C[i,j] += alpha * B[p,j]

Now the inner loop streams through rows of B and C. It is a scaled row addition: broadcast one value from A, multiply a vector from B, and accumulate it into C. There is no horizontal reduction, and the compiler sees a straightforward vector loop when the non-aliasing contract is available.

This order reuses one A element across an entire row, but it repeatedly visits C and rereads B for every row of A. Cache blocking will address both problems.

#A Real AVX2/FMA Row Kernel

First isolate the vectorizable inner operation. This implementation uses unaligned loads and stores and has a scalar tail, so neither addresses nor lengths need special treatment.

#include <cmath>
#include <cstddef>
#include <immintrin.h>

void add_scaled_row_avx2(float *output,
                         const float *input,
                         float alpha,
                         std::size_t length) {
    const __m256 scale = _mm256_set1_ps(alpha);
    std::size_t j = 0;

    for (; length - j >= 8; j += 8) {
        const __m256 x = _mm256_loadu_ps(input + j);
        const __m256 y = _mm256_loadu_ps(output + j);
        const __m256 result = _mm256_fmadd_ps(scale, x, y);
        _mm256_storeu_ps(output + j, result);
    }

    for (; j < length; ++j)
        output[j] = std::fma(alpha, input[j], output[j]);
}

Compile this function for AVX2 and FMA—for example with a dedicated target attribute or a translation unit built with -mavx2 -mfma—and dispatch to it only after checking processor support. AVX2 does not itself imply FMA in a runtime feature test.

An aligned packed path may replace loadu with load, but only when every row start and panel offset satisfies the instruction’s alignment. Padding the total allocation is not enough if the row stride destroys alignment on the next row.

#Cache Blocking with Complete Tails

Partition the output into row and column panels and the reduction dimension into depth panels. The logical computation becomes

$$ C_{I,J}\mathrel{+}=A_{I,P}B_{P,J} $$

for every triple of panels. If the active pieces of A, B, and C fit appropriate cache levels, values loaded for one update can serve many nearby updates before eviction.

The following macro-kernel calls the real AVX2 row kernel. The block sizes are parameters rather than alleged universal constants, and min-style tails are written without overflowing base + block.

#include <algorithm>
#include <cstddef>
#include <span>
#include <stdexcept>

void matmul_blocked_avx2(std::span<const float> a,
                         std::span<const float> b,
                         std::span<float> c,
                         std::size_t m,
                         std::size_t k,
                         std::size_t n,
                         std::size_t lda,
                         std::size_t ldb,
                         std::size_t ldc,
                         std::size_t row_block = 48,
                         std::size_t depth_block = 128,
                         std::size_t column_block = 128) {
    require_matrix(a.size(), m, k, lda);
    require_matrix(b.size(), k, n, ldb);
    require_matrix(c.size(), m, n, ldc);
    if (row_block == 0 || depth_block == 0 || column_block == 0)
        throw std::invalid_argument("matrix block size must be positive");
    if (m == 0 || n == 0)
        return;

    for (std::size_t i = 0; i < m; ++i)
        std::fill_n(c.data() + i * ldc, n, 0.0f);

    for (std::size_t ii = 0; ii < m;) {
        const std::size_t i_end = ii + std::min(row_block, m - ii);

        for (std::size_t jj = 0; jj < n;) {
            const std::size_t j_end =
                jj + std::min(column_block, n - jj);

            for (std::size_t pp = 0; pp < k;) {
                const std::size_t p_end =
                    pp + std::min(depth_block, k - pp);

                for (std::size_t i = ii; i < i_end; ++i) {
                    for (std::size_t p = pp; p < p_end; ++p) {
                        add_scaled_row_avx2(
                            c.data() + i * ldc + jj,
                            b.data() + p * ldb + jj,
                            a[i * lda + p],
                            j_end - jj);
                    }
                }
                pp = p_end;
            }
            jj = j_end;
        }
        ii = i_end;
    }
}

Every logical index remains within the extents validated at entry. j_end - jj may be any positive length, so the last column panel and its final SIMD vector are both safe. The block loops advance to their computed ends, which avoids unsigned overflow from blindly adding a fixed step near SIZE_MAX.

This is a robust teaching kernel, not yet a BLAS microkernel. It broadcasts one A value and updates one row at a time, leaving register reuse across output rows to the cache rather than exploiting it explicitly.

#Register Blocking

To reuse B in registers, compute several rows of C at once. A $6\times16$ AVX2 microkernel keeps twelve 8-float accumulators:

initialize c00 ... c51 to zero
for p in the packed depth panel
    b0 = load 8 values of B[p, j:j+8]
    b1 = load 8 values of B[p, j+8:j+16]
    for each of 6 output rows r
        ar = broadcast A[i+r, p]
        cr0 = fma(ar, b0, cr0)
        cr1 = fma(ar, b1, cr1)
store the twelve accumulators

One pair of B loads feeds twelve vector FMAs, and the independent accumulators hide FMA latency. The tile size is architecture-specific: vector width, register count, FMA latency and throughput, load ports, and address-generation capacity all influence it. A 6-by-16 choice suitable for one AVX2 core is not a law for AVX-512, Arm SVE, or even another AVX2 microarchitecture.

Full tiles take the hot path. Bottom and right edges need separate smaller kernels, masked operations where available, or zero-padded packed panels. Calling the full kernel on a partial tile and “copying only the valid answer” is still an out-of-bounds read unless the inputs were genuinely padded.

#Packing Panels

Blocking promises reuse only if cache layout cooperates. BLAS-style implementations usually pack panels into contiguous temporary buffers:

  • padding makes microkernel dimensions exact and gives tails defined zero values;
  • fixed strides remove address arithmetic from the hot loop;
  • controlled alignment enables aligned vector accesses;
  • compact panels avoid conflict patterns caused by unfortunate original strides;
  • the same packed B panel is reused by many A row panels.

Packing has a cost, so its loop order matters. Pack a panel once, use it many times, and amortize the copy. Tiny matrices may finish faster with the direct kernel because there is not enough reuse to repay packing.

Use RAII-owned buffers and check allocation failure. If using std::aligned_alloc, remember that the requested byte count must be a multiple of the alignment; rounding the row width does not necessarily round the whole allocation. Initialize padded elements before a microkernel reads them.

Kazushige Goto and Robert van de Geijn’s anatomy of high-performance matrix multiplication develops this packed macro-kernel/microkernel organization in detail.

#FMA and Numerical Results

_mm256_fmadd_ps(a, b, c) computes $ab+c$ with one rounding instead of rounding the product and sum separately. That is usually more accurate, but it can differ in the last bits from scalar multiply followed by add. Blocking and register tiling may also change the order in which partial sums are combined.

Floating-point addition is not associative:

$$ (x+y)+z\ne x+(y+z) $$

in general. Consequently, two correct matrix kernels need not be bitwise identical. Compare the optimized binary32 result with the wider reference using a documented absolute and relative tolerance, preferably also a normwise error. Include cancellation-heavy matrices, very small and very large magnitudes, zeros, and the application’s policy for infinities and NaNs.

The flag -ffast-math does much more than permit FMA: it allows reassociation and weakens behavior around NaNs, infinities, signed zero, and the floating-point environment. Use it only if those semantic changes are part of the contract. Explicit FMA intrinsics do not require granting all of them.

AMD’s Software Optimization Guide for Family 17h Processors is the primary architecture reference for validating assumptions on that processor family; measured clocks and instruction throughput still belong in the benchmark record.

#Benchmarking and Validation

Validate before timing. For many small rectangular shapes, compare the blocked kernel against the wider reference using random strides and padding. Include:

  • every dimension from zero through the SIMD width;
  • dimensions just below and above each block size;
  • tall, wide, and thin matrices—not just squares;
  • unaligned span offsets and padded leading dimensions;
  • $K=0$, identity matrices, zero matrices, and one-hot rows;
  • small integral floats, for which exact expected answers are easy;
  • random and cancellation-heavy floating-point inputs.

Fill padding with sentinels and verify it remains unchanged. Run with address and undefined-behavior sanitizers. Compare all $M\times N$ logical outputs, not a checksum alone; retain a checksum only in the timed harness to prevent dead-code elimination.

For performance, report $M$, $K$, $N$, all three strides, transpose flags, scalar type, thread count, affinity, compiler flags, library build, warm-up policy, and whether packing or allocation is timed. Sweep shapes and sizes. A square $1920\times1920$ benchmark says little about a neural-network layer shaped $1\times4096$ by $4096\times11008$.

Use a tuned BLAS library as the end-to-end baseline. Its sgemm interface also supports scaling and accumulation,

$$ C\leftarrow\alpha AB+\beta C, $$

plus transposed operands. The simpler overwrite-only function in this chapter corresponds to $\alpha=1$ and $\beta=0$.

Matrix multiplication is a model case because the final inner loop is almost comically small. The hard work is arranging that loop’s operands: dimensions make them meaningful, strides make them reachable, packing makes them regular, blocking makes them resident, and register tiling makes them reusable. SIMD is the last multiplication sign, not the first idea.
