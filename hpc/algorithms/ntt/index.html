Number-Theoretic Transform

The fast Fourier transform computes convolution quickly by evaluating polynomials at complex roots of unity. Its arithmetic is approximate. If the coefficients are integers and an exact modular result is acceptable—or can later be reconstructed—the same butterfly can run in a finite field.

This is the number-theoretic transform (NTT). It replaces complex multiplication with modular multiplication, floating-point error with algebraic preconditions, and unrestricted power-of-two lengths with lengths supported by the chosen prime.

Those preconditions are the algorithm. A modulus being prime is not enough; the field must contain a root of the exact transform order. Padding beyond that order, using a nonprimitive root, or reconstructing coefficients larger than the modulus produces perfectly deterministic wrong answers.

#Roots of Unity in a Finite Field

Let $q$ be prime. The nonzero residues modulo $q$ form a multiplicative group of order $q-1$. If $g$ is a primitive root and $n\mid(q-1)$, then

$$ \omega_n=g^{(q-1)/n}\pmod q $$ has order exactly $n$. We can define $$ A_k=\sum_{j=0}^{n-1}a_j\omega_n^{jk}\pmod q. $$

The inverse uses $\omega_n^{-1}$ and multiplies by $n^{-1}\bmod q$. Both inverses exist because the values are nonzero modulo a prime.

Pollard’s primary paper The Fast Fourier Transform in a Finite Field develops this construction and its use for integer-sequence convolution.

#A Concrete Field

We will use

$$ q=998244353=119\cdot2^{23}+1 $$

with primitive root $g=3$. This supports every power-of-two transform length through $2^{23}$. It does not support length $2^{24}$, and silently wrapping exponents does not manufacture the missing root.

All stored coefficients are canonical residues in $[0,q)$. Products fit in 64 bits:

$$ (q-1)^2<10^{18}<2^{64}. $$

The following C++20 transform is self-contained:

#include <algorithm>
#include <bit>
#include <cstddef>
#include <cstdint>
#include <span>
#include <stdexcept>

namespace ntt998 {

using u32 = std::uint32_t;
using u64 = std::uint64_t;

constexpr u32 modulus = 998244353;
constexpr u32 primitive_root = 3;
constexpr std::size_t maximum_length = std::size_t(1) << 23;

u32 power(u32 base, u64 exponent) {
    u32 result = 1;
    while (exponent != 0) {
        if (exponent & 1)
            result = u32(u64(result) * base % modulus);
        base = u32(u64(base) * base % modulus);
        exponent >>= 1;
    }
    return result;
}

void transform(std::span<u32> values, bool inverse = false) {
    std::size_t n = values.size();
    if (!std::has_single_bit(n) || n > maximum_length)
        throw std::invalid_argument("unsupported NTT length");
    for (u32 x : values)
        if (x >= modulus)
            throw std::invalid_argument("noncanonical NTT coefficient");

    for (std::size_t i = 1, reversed = 0; i < n; ++i) {
        std::size_t bit = n >> 1;
        while ((reversed & bit) != 0) {
            reversed ^= bit;
            bit >>= 1;
        }
        reversed ^= bit;
        if (i < reversed)
            std::swap(values[i], values[reversed]);
    }

    if (n > 1) {
        for (std::size_t length = 2;; length *= 2) {
            u32 root = power(primitive_root,
                             (modulus - 1) / u64(length));
            if (inverse)
                root = power(root, modulus - 2);

            std::size_t half = length / 2;
            for (std::size_t first = 0; first != n; first += length) {
                u32 w = 1;
                for (std::size_t j = 0; j != half; ++j) {
                    u32 even = values[first + j];
                    u32 odd = u32(u64(w) * values[first + j + half]
                                  % modulus);

                    u64 sum = u64(even) + odd;
                    values[first + j] =
                        u32(sum >= modulus ? sum - modulus : sum);
                    values[first + j + half] =
                        even >= odd ? even - odd : even + modulus - odd;
                    w = u32(u64(w) * root % modulus);
                }
            }

            if (length == n)
                break;
        }
    }

    if (inverse) {
        u32 inverse_n = power(u32(n), modulus - 2);
        for (u32 &x : values)
            x = u32(u64(x) * inverse_n % modulus);
    }
}

} // namespace ntt998

The loop structure matches the iterative radix-2 FFT: bit reversal, staged butterflies, reversed root for the inverse, and one final scaling. The differences are all in the arithmetic contract.

The exponent (modulus - 1) / length is integral because every accepted length divides $2^{23}$ and therefore divides $q-1$. Fermat’s theorem gives the inverse as $x^{q-2}$. A general NTT routine cannot hard-code these conclusions; it must verify or receive a proven modulus, root, and maximum order.

#Modular Convolution

Pointwise multiplication of transformed coefficient arrays gives cyclic convolution modulo $q$. Zero-padding to at least a.size() + b.size() - 1 turns it into linear convolution modulo $q$:

#include <limits>
#include <vector>

std::vector<ntt998::u32>
convolve_mod(std::span<const ntt998::u32> a,
             std::span<const ntt998::u32> b) {
    using namespace ntt998;
    if (a.empty() || b.empty())
        return {};

    constexpr std::size_t maximum =
        std::numeric_limits<std::size_t>::max();
    if (a.size() > maximum - b.size() + 1)
        throw std::length_error("convolution length overflow");
    std::size_t needed = a.size() + b.size() - 1;

    std::size_t n = 1;
    while (n < needed) {
        if (n >= maximum_length)
            throw std::length_error("convolution exceeds NTT field order");
        n *= 2;
    }

    std::vector<u32> fa(n, 0), fb(n, 0);
    std::copy(a.begin(), a.end(), fa.begin());
    std::copy(b.begin(), b.end(), fb.begin());

    transform(fa);
    transform(fb);
    for (std::size_t i = 0; i != n; ++i)
        fa[i] = u32(u64(fa[i]) * fb[i] % modulus);
    transform(fa, true);

    fa.resize(needed);
    return fa;
}

The input values must already lie in [0, modulus); transform checks them before mutation. Signed application coefficients can be mapped with a deliberate reduction such as

ntt998::u32 residue(std::int64_t x) {
    std::int64_t r = x % std::int64_t(ntt998::modulus);
    return ntt998::u32(r < 0 ? r + ntt998::modulus : r);
}

Reducing an out-of-range coefficient is an application decision. The low-level transform rejects it instead of guessing whether the caller intended a residue or made a range error.

#Modular Is Not Automatically Exact Integer Convolution

The NTT returns each coefficient modulo $q$. To interpret that residue as an ordinary nonnegative integer, the true coefficient must be smaller than $q$.

If a and b are nonnegative, bounded by $A$ and $B$, then every convolution coefficient is at most

$$ \min(|a|,|b|)AB. $$

A single-modulus result is uniquely recoverable as a nonnegative integer only when this bound is strictly less than modulus. Check the bound with division rather than overflowing the calculation itself:

terms <= (modulus - 1) / A / B

with zero handled separately.

For signed coefficients reconstructed into the centered interval $(-q/2,q/2]$, an absolute bound below $q/2$ is required. If the bound is larger, use several NTT-friendly primes and reconstruct with the Chinese remainder theorem. The product of the primes must exceed the nonnegative bound, or twice the signed absolute bound, and every chosen prime must support the padded transform length.

This is the exact-arithmetic counterpart of FFT error analysis. The NTT has no roundoff, but a violated coefficient bound aliases values by an exact multiple of $q$.

#Why This Prime Works

The factor $2^{23}$ in $q-1$ is what supports repeated radix-2 splitting. For a general desired length $n$, we need

  1. a modulus under which multiplication intermediates are safe or explicitly reduced;
  2. $n\mid(q-1)$;
  3. an element of order exactly $n$;
  4. a modular inverse of $n$;
  5. enough modulus product to reconstruct the intended coefficient range.

Testing only $\omega^n=1$ is insufficient: a root of smaller order also passes. If $n$ is a power of two, checking $\omega^{n/2}\ne1$ proves exact order once $\omega^n=1$. For arbitrary composite $n$, test against every prime divisor of $n$.

Primality and primitive-root claims should be established when defining a field, not rediscovered inside every transform. Fixed, reviewed parameter sets are easier to audit than user-supplied “prime and root” integers.

#Mapping the Butterfly to Hardware

The NTT trades complex floating-point operations for integer multiplication and modular reduction. The memory access pattern is almost identical to the FFT, including the irregular bit-reversal permutation and contiguous blocks within each stage.

The reference code uses % modulus after 64-bit products. Because the modulus is compile-time constant, an optimizing compiler can replace general division with multiplication by a reciprocal and corrections. Hand-written Barrett or Montgomery reduction can make that choice explicit and can be useful in SIMD kernels, but it also expands the proof surface.

Butterfly additions need only one conditional correction because both inputs are canonical residues. Deferring reductions across several operations can expose more instruction-level parallelism, but the widened range must be proved against the integer type at every stage.

SIMD support varies by limb width and ISA. Vectorizing several butterflies is straightforward conceptually; 64-bit products and lane-wise modular reduction are the limiting operations on many targets. Multiple independent transforms or blocks can provide cleaner parallelism than forcing one butterfly into an inconvenient vector shape.

Twiddle powers are exact field elements, so there is no numerical drift. Precomputed tables still trade multiplication and exponentiation setup for cache traffic. Reusing a plan for many transforms can amortize bit-reversal indices and stage roots just as in an FFT library.

#Validation

The strongest basic property is exact round-trip equality:

inverse(transform(a)) == a

for every supported length and canonical input. Also compare convolve_mod against the $O(nm)$ modular definition on randomized small arrays. Exercise lengths 1 and $2^{23}$, rejection of zero/non-power-of-two/too-large lengths, coefficients 0 and modulus - 1, empty convolution inputs, and padded lengths immediately on either side of a power of two.

Root tests should verify

$$ \omega^n=1,\qquad \omega^{n/2}\ne1 $$

for each supported radix-2 length above one. A convolution test alone may not reveal a scaling error if both reference and optimized paths accidentally use the same convention.

#Reproducible Evaluation

Report modulus, primitive root, maximum order, transform length distribution, forward/inverse mix, coefficient range, inclusion of allocation and root setup, reduction method, compiler flags, ISA target, CPU, and thread count. Distinguish transform throughput from end-to-end convolution and CRT reconstruction.

Compare with the FFT only under a shared application contract. A floating transform may support larger lengths and different coefficient ranges; an NTT may require several primes; their output guarantees are different. “Exact versus approximate” is not enough information to predict which complete pipeline is faster.

The NTT is elegant precisely because the butterfly survives unchanged. But complex roots existed for every length, while finite-field roots must be earned through factorization of $q-1$. Once the modulus, order, normalization, and coefficient bound are all explicit, the transform becomes a dependable exact convolution engine instead of a collection of competitive-programming constants.
