Fast Fourier Transform

The discrete Fourier transform is a dense matrix-vector multiplication with an extraordinary matrix. Its entries are powers of one complex root, and that algebraic repetition lets us reduce $n^2$ work to $n\log n$. The fast Fourier transform is therefore not one algorithm but a family of factorizations of the DFT.

We will derive the radix-2 Cooley–Tukey transform, implement an in-place iterative C++20 core, use it for linear convolution, and then examine the parts hidden by big-O notation: permutation, twiddle generation, vectorization, inverse scaling, and floating-point error.

Our code accepts a nonempty power-of-two length and uses std::complex<double>. Other lengths need mixed-radix, Bluestein, Rader, or library support; silently padding a transform changes the mathematical object unless the operation is specifically convolution.

#The Transform Pair

For $n$ complex samples $a_0,\ldots,a_{n-1}$, define

$$ \omega_n=e^{-2\pi i/n} $$ and the forward DFT $$ A_k=\sum_{j=0}^{n-1}a_j\omega_n^{jk}. $$ Our inverse convention reverses the sign and divides by $n$: $$ a_j=\frac1n\sum_{k=0}^{n-1}A_k\omega_n^{-jk}. $$

Libraries use several scaling conventions. Some leave both directions unscaled, some split the factor symmetrically, and some match the convention above. Composing code with different conventions can produce an answer that is exactly wrong by a factor of $n$.

A literal implementation evaluates every pair $(j,k)$ and costs $O(n^2)$. It is valuable as a small oracle, but it ignores the identities among roots.

#Splitting Even and Odd Indices

Separate the input into its even and odd subsequences. For $0\le k<n/2$, let $E_k$ and $O_k$ be their length-$n/2$ transforms. Since $\omega_n^2=\omega_{n/2}$,

$$ \begin{aligned} A_k &=E_k+\omega_n^kO_k,\\ A_{k+n/2}&=E_k-\omega_n^kO_k. \end{aligned} $$

One multiplication by the twiddle factor $\omega_n^k$ and two additions form a butterfly:

u --------(+ )-------- u + w v
       \  /
        \/
        /\
       /  \
v --(times w)--(- )--- u - w v

Applying the split recursively gives

$$ T(n)=2T(n/2)+O(n)=O(n\log n). $$

Cooley and Tukey’s primary 1965 paper, An Algorithm for the Machine Calculation of Complex Fourier Series, develops the general factorization for composite lengths. Radix 2 is the simplest special case, not a fundamental restriction of the FFT idea.

#An Iterative Radix-2 FFT

A recursive decimation-in-time implementation naturally gathers even and odd elements. To perform the same butterflies in place and iteratively, first permute indices by reversing their $\log_2 n$ bits. Then execute stages of length 2, 4, 8, and so on.

#include <algorithm>
#include <bit>
#include <cmath>
#include <complex>
#include <cstddef>
#include <numbers>
#include <span>
#include <stdexcept>

using complex64 = std::complex<double>;

void fft(std::span<complex64> values, bool inverse = false) {
    std::size_t n = values.size();
    if (!std::has_single_bit(n))
        throw std::invalid_argument("FFT length must be a nonzero power of two");

    // In-place bit-reversal permutation.
    for (std::size_t i = 1, reversed = 0; i < n; ++i) {
        std::size_t bit = n >> 1;
        while ((reversed & bit) != 0) {
            reversed ^= bit;
            bit >>= 1;
        }
        reversed ^= bit;
        if (i < reversed)
            std::swap(values[i], values[reversed]);
    }

    if (n > 1) {
        for (std::size_t length = 2;; length *= 2) {
            double angle = (inverse ? 2.0 : -2.0)
                         * std::numbers::pi_v<double> / double(length);
            complex64 root(std::cos(angle), std::sin(angle));
            std::size_t half = length / 2;

            for (std::size_t first = 0; first != n; first += length) {
                complex64 w(1, 0);
                for (std::size_t j = 0; j != half; ++j) {
                    complex64 even = values[first + j];
                    complex64 odd = w * values[first + j + half];
                    values[first + j] = even + odd;
                    values[first + j + half] = even - odd;
                    w *= root;
                }
            }

            if (length == n)
                break; // prevents the next doubling from overflowing
        }
    }

    if (inverse)
        for (complex64 &x : values)
            x /= double(n);
}

The implementation has explicit behavior at every awkward boundary:

  • length zero is rejected rather than passed to log2 or division;
  • length one is a valid identity transform;
  • non-power-of-two lengths are rejected;
  • the stage loop exits before doubling the final length;
  • inverse scaling happens exactly once.

The forward sign is negative, matching the definition above. Changing just the sign or just the scaling creates a different convention; tests should treat the forward/inverse pair as one interface.

#Linear Convolution

For sequences $a$ and $b$, linear convolution is

$$ c_k=\sum_{i+j=k}a_i b_j. $$

The convolution theorem turns this into pointwise multiplication in the frequency domain. To avoid circular wraparound, pad to at least a.size() + b.size() - 1:

#include <limits>
#include <vector>

std::vector<double> convolve(std::span<const double> a,
                             std::span<const double> b) {
    if (a.empty() || b.empty())
        return {};

    constexpr std::size_t maximum =
        std::numeric_limits<std::size_t>::max();
    if (a.size() > maximum - b.size() + 1)
        throw std::length_error("convolution length overflow");
    std::size_t needed = a.size() + b.size() - 1;

    std::size_t n = 1;
    while (n < needed) {
        if (n > maximum / 2)
            throw std::length_error("FFT length overflow");
        n *= 2;
    }

    std::vector<complex64> fa, fb;
    if (n > fa.max_size() || n > fb.max_size())
        throw std::length_error("FFT allocation is too large");
    fa.assign(n, complex64(0, 0));
    fb.assign(n, complex64(0, 0));

    for (std::size_t i = 0; i != a.size(); ++i) fa[i] = a[i];
    for (std::size_t i = 0; i != b.size(); ++i) fb[i] = b[i];

    fft(fa);
    fft(fb);
    for (std::size_t i = 0; i != n; ++i)
        fa[i] *= fb[i];
    fft(fa, true);

    std::vector<double> result(needed);
    for (std::size_t i = 0; i != needed; ++i)
        result[i] = fa[i].real();
    return result;
}

Padding is exact with respect to linear versus cyclic convolution, but the arithmetic is still floating point. A small imaginary residual after the inverse is normal. A large residual indicates an implementation, conditioning, overflow, or input-scale problem and should not be discarded silently.

Rounding the real parts to integers is justified only when an application-specific error bound proves that every result lies within less than one half of the correct integer. Large coefficients, long transforms, or adversarial cancellation can break that assumption. The number-theoretic transform provides exact modular convolution when an appropriate finite field exists.

#What the Machine Executes

Each stage performs $n/2$ independent butterflies. Within one block, reads and writes are contiguous, and the same twiddle sequence is reused by every block of that stage. These properties create several optimization paths.

#Twiddle factors

The reference code computes one sine/cosine pair per stage and obtains later twiddles by repeated complex multiplication. This is cheap, but recurrence error accumulates as w drifts away from the unit circle. Alternatives include precomputed tables, computing twiddles in short independently restarted groups, or periodically recalculating them from an angle.

Computing sin and cos inside every butterfly is usually too expensive. A table costs memory traffic. The best compromise depends on transform length, precision, reuse, and cache capacity.

#Complex layout and SIMD

std::complex<double> normally stores interleaved real and imaginary parts, which is convenient for scalar complex multiplication. SIMD kernels may prefer separate real and imaginary vectors or carefully shuffled interleaved data. The butterfly itself has ample parallelism; moving values into the desired lane arrangement can cost as much as its arithmetic.

Vectorize across several butterflies that use compatible twiddles, unroll to keep independent operations in flight, and handle the final partial vector explicitly. Radix 4 or higher combines stages, reducing some loads and twiddle multiplications at the price of a larger kernel.

#Permutation

Bit reversal is $O(n)$ and therefore invisible in the asymptotic bound, but it performs an irregular permutation before useful arithmetic begins. Table-based bit reversal, blocked permutation, and Stockham autosort variants trade extra storage or passes for more regular access. Whether the separate permutation matters depends on how often the same plan and layout are reused.

This is why production FFT libraries plan rather than expose one fixed loop. The primary FFTW3 design paper describes codelets, planner-selected decompositions, cache considerations, and machine adaptation across transform shapes.

#Floating-Point Error

The FFT replaces one sum of $n$ terms with $\log_2 n$ stages of additions and multiplications. Every operation rounds, computed roots are approximate, and twiddle recurrences add their own drift. Primary work on the accumulation of FFT roundoff gives error bounds under explicit models; there is no universal decimal-digit promise independent of data and scale.

Useful checks include:

  • forward followed by inverse, compared with the original input;
  • Parseval’s identity under the chosen normalization;
  • comparison with the $O(n^2)$ DFT at small sizes;
  • convolution versus a direct long-double accumulation;
  • maximum imaginary residual for nominally real output.

Absolute tolerance alone is misleading across scales. Report an error such as

$$ \frac{\lVert\widehat x-x\rVert_2} {\max(1,\lVert x\rVert_2)} $$

and also inspect componentwise error when small coefficients matter. Inputs near DBL_MAX, NaN, and infinities need a stated policy; the core routine permits IEEE propagation rather than pretending they are ordinary finite signals.

Compiler flags are part of this policy. Fast-math may reassociate complex expressions, contract operations, ignore signed zero, and assume finite inputs. It can improve a benchmark while changing both reproducibility and exceptional-value behavior.

#Reproducible Evaluation

Record transform direction, length distribution, in-place versus out-of-place layout, precision, complex representation, twiddle strategy, inclusion of planning/allocation, compiler flags, ISA target, CPU, and thread count. Warm repeated transforms and one-shot cold transforms answer different questions.

Verify output before timing. The historical companion directory for this chapter contains several recursive and iterative sketches, but some variants transform only a prefix, repeatedly transform already transformed data, or remain incomplete experiments. They are useful for reconstructing the intended recursion and permutation work, not as evidence for a performance record.

Benchmark the full application as well as the FFT kernel. For convolution, padding and two forward transforms may dominate small inputs. For repeated transforms of the same shape, planning and twiddle tables amortize. For real-valued data, a real-to-complex transform can avoid nearly half the redundant spectrum, but it has a different interface and packing contract.

The FFT’s artistry lies in matching algebraic factorization to a memory hierarchy. The butterfly proves the asymptotic improvement; a reliable implementation must also choose a convention, permute safely, scale the inverse, manage twiddles, and quantify the error it introduces.
