String Searching

Finding a byte in memory is a reduction: compare many positions and return the first match. Finding a string is a filtering problem: reject almost every position cheaply, then verify the survivors.

That distinction matters more than the catalog of classical algorithms. On ordinary text, a two-byte filter may eliminate hundreds of candidates with a few vector instructions. On repetitive input, the same filter may accept every position, and only a worst-case linear algorithm prevents quadratic behavior.

#The Contract

Let the haystack contain $n$ bytes and the needle contain $m$ bytes. We return the smallest $i$ such that

$$ \mathtt{haystack}[i..i+m)=\mathtt{needle}[0..m), $$

or report no match. By the convention used by std::string_view::find, the empty needle matches at position zero.

This chapter searches bytes. UTF-8 code points, canonical equivalence, case folding, and locale-aware matching are different contracts. A byte search can locate an ASCII delimiter in UTF-8 safely, but it does not implement a general Unicode search.

The reference implementation is deliberately boring:

#include <cstring>
#include <string_view>

std::size_t find_naive(std::string_view text,
                       std::string_view pattern) {
    if (pattern.empty())
        return 0;
    if (pattern.size() > text.size())
        return std::string_view::npos;

    const std::size_t candidates = text.size() - pattern.size() + 1;
    for (std::size_t i = 0; i < candidates; ++i)
        if (std::memcmp(text.data() + i,
                        pattern.data(), pattern.size()) == 0)
            return i;
    return std::string_view::npos;
}

Its worst case is $O(nm)$: searching for aaaaab in a long run of a rechecks nearly the entire prefix at each position. For many real inputs, however, memcmp rejects on the first byte and the constant is small. A better implementation should preserve that common-case economy without inheriting the worst case.

#What the Classical Algorithms Buy

Knuth–Morris–Pratt preprocesses the needle’s borders and never moves backward in the text, guaranteeing $O(n+m)$ comparisons. Its inner loop follows failure links, which can be branchy and dependent.

Boyer–Moore compares from the end and uses mismatches to skip candidate positions. Horspool’s simplified bad-character table is often effective for medium or long needles over a large alphabet. Its best cases inspect much less than $n$ text, but the skip behavior depends on the input and variant.

The Two-Way algorithm factors the needle around a critical position and combines forward comparisons with periodicity information. It uses constant auxiliary space and guarantees linear time. Variants of it are used in production C libraries because they handle both random and periodic strings without a large preprocessing table.

No asymptotic theorem selects one winner for every $m$. Implementations normally dispatch: an empty or one-byte needle has a specialized path, short needles use compact filters, and longer or adversarial searches use a linear-time core.

#Filtering Candidate Starts with AVX2

For a match of length $m\ge2$, both the first and last bytes must agree:

$$ T[i]=P[0] \quad\text{and}\quad T[i+m-1]=P[m-1]. $$

AVX2 can test 32 starting positions at once. The following function never loads beyond the haystack: the vector loop runs only when all 32 candidate starts—and therefore both 32-byte loads—are valid.

#include <bit>
#include <cstdint>
#include <cstring>
#include <immintrin.h>
#include <string_view>

std::size_t find_avx2(std::string_view text,
                      std::string_view pattern) {
    const std::size_t n = text.size();
    const std::size_t m = pattern.size();

    if (m == 0)
        return 0;
    if (m > n)
        return std::string_view::npos;
    if (m == 1) {
        const void* p = std::memchr(text.data(),
                                   static_cast<unsigned char>(pattern[0]), n);
        return p ? std::size_t(static_cast<const char*>(p) - text.data())
                 : std::string_view::npos;
    }

    const std::size_t candidates = n - m + 1;
    const __m256i first = _mm256_set1_epi8(pattern.front());
    const __m256i last = _mm256_set1_epi8(pattern.back());

    std::size_t i = 0;
    for (; i + 32 <= candidates; i += 32) {
        const __m256i a = _mm256_loadu_si256(
            reinterpret_cast<const __m256i*>(text.data() + i));
        const __m256i b = _mm256_loadu_si256(
            reinterpret_cast<const __m256i*>(text.data() + i + m - 1));

        uint32_t mask = uint32_t(_mm256_movemask_epi8(
            _mm256_and_si256(_mm256_cmpeq_epi8(a, first),
                             _mm256_cmpeq_epi8(b, last))));

        while (mask != 0) {
            unsigned bit = unsigned(std::countr_zero(mask));
            std::size_t candidate = i + bit;
            if (std::memcmp(text.data() + candidate,
                            pattern.data(), m) == 0)
                return candidate;
            mask &= mask - 1;
        }
    }

    for (; i < candidates; ++i)
        if (text[i] == pattern.front()
            && text[i + m - 1] == pattern.back()
            && std::memcmp(text.data() + i, pattern.data(), m) == 0)
            return i;

    return std::string_view::npos;
}

Compile this function only for an AVX2 target and dispatch to a scalar implementation on unsupported CPUs. Loading through an intrinsic pointer is the interface expected by x86 compilers, but it does not make overreading an allocation legal; the loop bound is what provides safety.

For independent uniformly distributed bytes, a first-byte filter accepts about $1/256$ of positions and two independent byte tests about $1/65536$. Natural language is neither uniform nor independent, but the reduction is often still dramatic. When the needle begins and ends with common bytes, selecting two rare internal bytes can improve the filter. Their offsets must then be included in the second load and in the bounds proof.

Repetitive data is the failure mode. Searching for aaaaaaaaab in aaaa... makes the first-byte test useless and the last-byte test decisive; searching for an all-a pattern makes both useless and calls memcmp at every position. A production search can count failed verifications and switch to Two-Way after the filter stops being selective.

#Why memchr Deserves Its Own Path

The one-byte case has no verification step and no preprocessing. Standard C libraries provide highly tuned memchr implementations with architecture dispatch, vector loops, safe page-boundary handling, and small-input paths. Replacing them with a hand-written AVX2 loop is unlikely to improve a whole program and may lose portability.

The same idea extends to two- and three-byte needles: compact specialized loops can avoid a general algorithm’s setup. Dispatch itself has a cost, so the length thresholds should be measured on the target library and workload.

#Hashes and Multiple Patterns

Rabin–Karp computes a rolling fingerprint for each $m$-byte window and verifies positions whose fingerprint matches the needle. It is useful when many windows share work or when several needles use the same hash machinery. A hash match is not normally proof of equality; verification preserves exact semantics. Adversarial inputs also require a keyed or otherwise robust strategy if collision-driven worst cases are a security concern.

Searching for hundreds of patterns independently wastes text bandwidth. Aho–Corasick builds an automaton that advances all prefix states in one pass and reports every matched pattern. High-performance regular-expression engines go further, combining literal filters, finite automata, and SIMD. The optimization unit is the entire pattern set, not one call to find.

#Benchmarking Search

Search time depends on more than $(n,m)$. Record at least:

  • whether a match exists and where the first match occurs;
  • needle length and periodicity;
  • alphabet size and byte distribution;
  • the number of false candidates reaching verification;
  • whether preprocessing is amortized over one or many haystacks;
  • cache state and total bytes read.

A benchmark containing only absent random needles measures the filter’s happiest path. Add matches at the beginning and end, one-byte needles, long common prefixes, low-alphabet data, and periodic adversarial cases.

Differential testing is straightforward: compare every result with std::string_view::find over randomized byte strings, then enumerate all short strings over a two- or three-symbol alphabet. Small exhaustive tests are particularly good at finding tail errors and empty-pattern disagreements. Run AddressSanitizer as well; a vector search can return correct answers for years while still reading one byte beyond an allocation.

#A Practical Dispatch

A robust exact search commonly looks like this:

  1. handle empty, oversized, and one-byte needles;
  2. use a compact SIMD or word-at-a-time filter for short and medium needles;
  3. verify candidate positions with a tuned equality routine;
  4. fall back to a worst-case linear algorithm when periodicity or excessive candidates make filtering ineffective;
  5. use a multi-pattern algorithm when the query set, rather than one needle, is reused.

The fastest comparison is the one not performed. SIMD wins here by rejecting candidate positions, while linear-time string algorithms win by proving which positions can be skipped. Good library implementations use both arguments.
