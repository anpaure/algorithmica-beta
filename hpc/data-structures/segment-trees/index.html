Algorithmica βSegment Trees

Segment Trees

Segment trees are a useful test of data-structure engineering because the asymptotic answer is known before optimization begins. Point updates and range reductions both take $O(\log n)$ time; the interesting questions are how many nodes are touched, how they are laid out, and which operation receives the simpler inner loop.

We start with one precise interface over a zero-initialized array:

  • add(i, delta) changes $a_i$ by delta;
  • prefix_sum(k) returns the sum on the half-open range $[0,k)$;
  • range_sum(l,r) returns the sum on $[l,r)$.

Thus prefix_sum(0) and range_sum(k,k) are zero, while prefix_sum(n) includes the entire array. An update requires $i<n$; a query permits an endpoint equal to $n$.

#Range Coverage

A binary segment tree associates every node with a half-open interval. Its two children partition that interval at the midpoint. Any query $[l,r)$ can be represented by $O(\log n)$ disjoint nodes: while moving both endpoints toward their least common ancestor, take a right child exposed on the left boundary and a left child exposed on the right boundary.

The full-coverage test for a node interval $[l_b,r_b)$ is

$$ l\le l_b \quad\text{and}\quad r_b\le r, $$

not a comparison between the node’s right boundary and both query boundaries. Disjointness is $r\le l_b$ or $r_b\le l$. Mixing these predicates was the source of an especially plausible recursive implementation that returned an entire node lying before the query.

For $n>0$, a recursively split tree with exactly the original leaves has $2n-1$ logical nodes. A flat power-of-two layout instead pads to

$$ p=2^{\lceil\log_2 n\rceil} $$

leaves and stores $2p-1$ useful nodes. These are different layouts and should not borrow each other’s size claims.

#A Bottom-Up Sum Tree

Padding with zero-valued leaves makes every real leaf occupy p + i and every parent occupy half its child’s index. The standard two-endpoint query then works for every $n$, including non-powers of two, without a special leaf permutation.

The implementation below checks all public bounds. Signed overflow is not allowed to become undefined behavior: construction and queries throw on an unrepresentable result, and an update validates its complete root path before changing any cell.

#include <array>
#include <bit>
#include <cstddef>
#include <cstdint>
#include <limits>
#include <span>
#include <stdexcept>
#include <vector>

std::int64_t checked_add_i64(std::int64_t left,
                             std::int64_t right) {
    if (right > 0
        && left > std::numeric_limits<std::int64_t>::max() - right)
        throw std::overflow_error("signed sum overflow");
    if (right < 0
        && left < std::numeric_limits<std::int64_t>::min() - right)
        throw std::overflow_error("signed sum overflow");
    return left + right;
}

std::int64_t checked_sub_i64(std::int64_t left,
                             std::int64_t right) {
    if (right > 0
        && left < std::numeric_limits<std::int64_t>::min() + right)
        throw std::overflow_error("signed difference overflow");
    if (right < 0
        && left > std::numeric_limits<std::int64_t>::max() + right)
        throw std::overflow_error("signed difference overflow");
    return left - right;
}

class segment_sum_tree {
public:
    explicit segment_sum_tree(
        std::span<const std::int64_t> values
    ) : size_(values.size()), base_(choose_base(size_)) {
        if (base_ > tree_.max_size() / 2)
            throw std::length_error("segment-tree allocation overflow");

        tree_.assign(base_ * 2, 0);
        for (std::size_t i = 0; i < size_; ++i)
            tree_[base_ + i] = values[i];

        for (std::size_t node = base_; node-- > 1;)
            tree_[node] = checked_add_i64(
                tree_[node * 2],
                tree_[node * 2 + 1]
            );
    }

    void add(std::size_t index, std::int64_t delta) {
        if (index >= size_)
            throw std::out_of_range("update index is outside the array");

        constexpr std::size_t path_capacity =
            std::numeric_limits<std::size_t>::digits + 1;
        std::array<std::size_t, path_capacity> path{};
        std::size_t count = 0;

        for (std::size_t node = base_ + index;
             node != 0;
             node /= 2)
            path[count++] = node;

        for (std::size_t i = 0; i < count; ++i)
            static_cast<void>(
                checked_add_i64(tree_[path[i]], delta)
            );
        for (std::size_t i = 0; i < count; ++i)
            tree_[path[i]] =
                checked_add_i64(tree_[path[i]], delta);
    }

    std::int64_t range_sum(std::size_t left,
                           std::size_t right) const {
        if (left > right || right > size_)
            throw std::out_of_range("invalid half-open range");

        std::size_t first = base_ + left;
        std::size_t last = base_ + right;
        std::int64_t left_sum = 0;
        std::int64_t right_sum = 0;

        while (first < last) {
            if ((first & 1U) != 0)
                left_sum =
                    checked_add_i64(left_sum, tree_[first++]);
            if ((last & 1U) != 0)
                right_sum =
                    checked_add_i64(tree_[--last], right_sum);
            first /= 2;
            last /= 2;
        }

        return checked_add_i64(left_sum, right_sum);
    }

    std::int64_t prefix_sum(std::size_t count) const {
        return range_sum(0, count);
    }

    std::size_t size() const noexcept {
        return size_;
    }

private:
    static std::size_t choose_base(std::size_t size) {
        if (size <= 1)
            return 1;

        constexpr std::size_t digits =
            std::numeric_limits<std::size_t>::digits;
        constexpr std::size_t largest_safe_base =
            std::size_t{1} << (digits - 2);
        if (size > largest_safe_base)
            throw std::length_error("segment-tree index overflow");
        return std::bit_ceil(size);
    }

    std::size_t size_;
    std::size_t base_;
    std::vector<std::int64_t> tree_;
};

The two accumulators preserve left-to-right order. Addition does not need that distinction, but the same loop can support any associative operation with an identity element, including non-commutative ones, if the right accumulator prepends rather than appends its nodes.

The empty tree still owns a two-cell implementation buffer with base = 1. It accepts the empty range and rejects every point update. Treating this small allocation as an implementation detail is simpler than giving zero a fictitious tree height and then subtracting one from it.

#Fenwick Trees

For prefix sums, many segment-tree values are redundant. A Fenwick tree stores one value for every original element, using one-based index $i$ for the interval

$$ [i-\operatorname{lowbit}(i),\,i). $$

Here lowbit(i) is the least significant set bit. With an unsigned index,

class fenwick_sum_tree {
public:
    explicit fenwick_sum_tree(std::size_t size)
        : size_(size) {
        if (size_ == std::numeric_limits<std::size_t>::max()
            || size_ + 1 > tree_.max_size())
            throw std::length_error("Fenwick-tree allocation overflow");
        tree_.assign(size_ + 1, 0);
    }

    void add(std::size_t index, std::int64_t delta) {
        if (index >= size_)
            throw std::out_of_range("update index is outside the array");

        constexpr std::size_t path_capacity =
            std::numeric_limits<std::size_t>::digits + 1;
        std::array<std::size_t, path_capacity> path{};
        std::size_t count = 0;

        std::size_t node = index + 1;
        while (node <= size_) {
            path[count++] = node;
            const std::size_t step = lowbit(node);
            if (step > size_ - node)
                break;
            node += step;
        }

        for (std::size_t i = 0; i < count; ++i)
            static_cast<void>(
                checked_add_i64(tree_[path[i]], delta)
            );
        for (std::size_t i = 0; i < count; ++i)
            tree_[path[i]] =
                checked_add_i64(tree_[path[i]], delta);
    }

    std::int64_t prefix_sum(std::size_t count) const {
        if (count > size_)
            throw std::out_of_range("prefix endpoint is outside the array");

        std::int64_t result = 0;
        for (std::size_t node = count;
             node != 0;
             node &= node - 1)
            result = checked_add_i64(result, tree_[node]);
        return result;
    }

    std::int64_t range_sum(std::size_t left,
                           std::size_t right) const {
        if (left > right || right > size_)
            throw std::out_of_range("invalid half-open range");
        return checked_sub_i64(
            prefix_sum(right),
            prefix_sum(left)
        );
    }

    std::size_t size() const noexcept {
        return size_;
    }

private:
    static std::size_t lowbit(std::size_t value) noexcept {
        return value & (~value + 1);
    }

    std::size_t size_;
    std::vector<std::int64_t> tree_;
};

Unsigned arithmetic makes ~i + 1 well-defined modulo $2^w$. The equivalent signed expression i & -i is safe only after proving that negation cannot overflow. The update also checks step > n - i before adding, so its loop cannot wrap beyond SIZE_MAX.

No power-of-two assumption is needed. The update stops at $n$, and the prefix walk only clears bits of an endpoint already in $[0,n]$:

A Fenwick range sum subtracts two prefixes. This requires an inverse operation. Integer addition forms a group while representable, and XOR is its own inverse; minimum, maximum, and string concatenation do not have the required inverse. A binary segment tree needs only associativity and an identity—a monoid—so it supports those operations without pretending that one prefix can “cancel” another.

#Wide Segment Trees

A binary tree uses one scalar from each fetched cache line. A wide tree instead groups $B$ children in one node. For dynamic prefix sums, store the $B$ in-node prefixes. A query reads one prefix per level; an update adds its delta to a suffix of every node on the path:

For arbitrary $n$, define $m_0=n$ and

$$ m_{h+1}=\left\lceil\frac{m_h}{B}\right\rceil. $$

One level is allocated for each $m_h>1$, plus the level that directly stores the final group. Replacing the ceiling with m / B undercounts the height whenever a partial group propagates upward—for example, $B^2+1$ elements need three levels, not two.

The following portable implementation stores each level separately. Every physical node has $B$ initialized lanes; lanes beyond the logical tail are zero padding, not nonexistent objects.

template <std::size_t Branch = 16>
class wide_prefix_sum_tree {
    static_assert(Branch >= 2);

    struct level_data {
        std::size_t child_count = 0;
        std::vector<std::int64_t> prefix;
    };

public:
    explicit wide_prefix_sum_tree(std::size_t size)
        : size_(size) {
        std::size_t children = size_;
        while (children != 0) {
            const std::size_t nodes = ceil_div(children, Branch);
            level_data level;
            level.child_count = children;
            if (nodes > level.prefix.max_size() / Branch)
                throw std::length_error(
                    "wide-tree allocation overflow"
                );
            level.prefix.assign(nodes * Branch, 0);
            levels_.push_back(std::move(level));

            if (nodes == 1)
                break;
            children = nodes;
        }
    }

    void add(std::size_t index, std::int64_t delta) {
        if (index >= size_)
            throw std::out_of_range("update index is outside the array");

        std::size_t child = index;
        for (const level_data& level : levels_) {
            const std::size_t node = child / Branch;
            const std::size_t slot = child % Branch;
            const std::size_t base = node * Branch;
            for (std::size_t lane = slot; lane < Branch; ++lane)
                static_cast<void>(checked_add_i64(
                    level.prefix[base + lane],
                    delta
                ));
            child = node;
        }

        child = index;
        for (level_data& level : levels_) {
            const std::size_t node = child / Branch;
            const std::size_t slot = child % Branch;
            const std::size_t base = node * Branch;
            for (std::size_t lane = slot; lane < Branch; ++lane)
                level.prefix[base + lane] = checked_add_i64(
                    level.prefix[base + lane],
                    delta
                );
            child = node;
        }
    }

    std::int64_t prefix_sum(std::size_t count) const {
        if (count > size_)
            throw std::out_of_range("prefix endpoint is outside the array");

        std::int64_t result = 0;
        std::size_t remaining = count;

        for (const level_data& level : levels_) {
            const std::size_t width = remaining % Branch;
            if (width != 0) {
                const std::size_t node = remaining / Branch;
                const std::size_t position =
                    node * Branch + width - 1;
                result = checked_add_i64(
                    result,
                    level.prefix.at(position)
                );
            }
            remaining /= Branch;
        }

        if (remaining != 0) {
            if (remaining != 1 || levels_.empty())
                throw std::logic_error("invalid wide-tree height");
            result = checked_add_i64(
                result,
                levels_.back().prefix.back()
            );
        }

        return result;
    }

    std::int64_t range_sum(std::size_t left,
                           std::size_t right) const {
        if (left > right || right > size_)
            throw std::out_of_range("invalid half-open range");
        return checked_sub_i64(
            prefix_sum(right),
            prefix_sum(left)
        );
    }

    std::size_t size() const noexcept {
        return size_;
    }

    std::size_t height() const noexcept {
        return levels_.size();
    }

private:
    static std::size_t ceil_div(std::size_t value,
                                std::size_t divisor) noexcept {
        return value / divisor
             + static_cast<std::size_t>(value % divisor != 0);
    }

    std::size_t size_;
    std::vector<level_data> levels_;
};

The query decomposes count into base-$B$ digits. A nonzero digit selects one stored prefix at that level; the final leading digit selects the root total. This handles count == n even when $n$ is an exact power of $B$, a boundary case that disappears if the implementation assumes there is always a partial tail.

For an update at in-node position $k$, the affected prefix lanes are

$$ j\ge k. $$

A mask using $j>k$ misses the prefix ending at the updated element. A SIMD implementation broadcasts the delta, masks with this greater-or-equal suffix, and adds full vectors. The scalar reference uses the same inequality and is suitable as a differential oracle. See SIMD masking, moving data, and horizontal reductions for target-specific implementations.

Padding lanes are deliberately updated when they lie in the suffix. The last physical lane then remains the total of the logical partial node, which is exactly the value its parent needs. No query exposes a padded lane as an array element.

#Choosing a Structure

The three layouts optimize different things:

  • A binary segment tree stores more values but handles any monoid and general ranges directly.
  • A Fenwick tree uses $n+1$ scalars and gives very small loops for an invertible prefix operation.
  • A wide prefix tree shortens the dependency chain, at the cost of updating $B$ lanes per level and storing padded nodes.

The total wide-tree storage is

$$ B\left\lceil\frac{n}{B}\right\rceil +B\left\lceil\frac{\lceil n/B\rceil}{B}\right\rceil+\cdots, $$

which is $O(n)$ but not exactly $nB/(B-1)$ because every partial level rounds up. Its optimal branch factor depends on scalar width, vector ISA, update/query ratio, cache-line size, and contention.

Benchmark half-open boundary cases before timing: $n=0$, $n=1$, $B-1$, $B$, $B+1$, $B^2-1$, $B^2$, and $B^2+1$. Then use randomized differential tests against a plain array. Performance results should report query mix, arithmetic width, overflow policy, compiler target, hardware, and whether timings measure independent throughput or a dependency chain.

The wide-prefix idea is closely related to the layouts evaluated by Pibiri and Venturini in “Practical Trade-Offs for the Prefix-Sum Problem”. Their results motivate the design; they do not replace validation on the machine and workload where the structure will run.
