Range Minimum Query

The minimum of an array is easy to compute and impossible to undo. That second property is what makes static range-minimum queries unusually fast.

Given an immutable array $a$, the range minimum query (RMQ) asks for

$$ \min\{a_l,a_{l+1},\ldots,a_{r-1}\} $$

on a half-open interval $[l,r)$. We will build the array once and answer many queries. Updates belong to a different problem; a segment tree trades constant query time for $O(\log n)$ queries and updates.

#Overlapping Is Harmless

Precompute the minimum of every interval whose length is a power of two:

$$ t[k][i] =\min\{a_i,\ldots,a_{i+2^k-1}\}. $$ The recurrence $$ t[k][i] =\min(t[k-1][i],t[k-1][i+2^{k-1}]) $$

builds level $k$ from two adjacent intervals at level $k-1$.

For a query of length $L=r-l$, choose $k=\lfloor\log_2L\rfloor$. Two length-$2^k$ intervals, one starting at $l$ and one ending at $r$, cover the query:

$$ \operatorname{rmq}(l,r) =\min(t[k][l],t[k][r-2^k]). $$ They may overlap. This is correct because minimum is idempotent: $$ \min(x,x)=x. $$

The same sparse-table query works for maximum, gcd, bitwise AND, and other idempotent associative operations. It does not work for sum: elements in the overlap would be counted twice.

#A Level-Major Sparse Table

Store each level contiguously. Construction then performs sequential reads from one level and sequential writes to the next:

#include <algorithm>
#include <bit>
#include <cassert>
#include <cstddef>
#include <utility>
#include <vector>

class SparseRMQ {
    std::vector<std::vector<int>> table;

public:
    SparseRMQ() = default;

    explicit SparseRMQ(std::vector<int> values) {
        if (values.empty())
            return;

        const std::size_t n = values.size();
        const unsigned levels = unsigned(std::bit_width(n));
        table.resize(levels);
        table[0] = std::move(values);

        for (unsigned k = 1; k < levels; ++k) {
            const std::size_t half = std::size_t(1) << (k - 1);
            const std::size_t length = half * 2;
            const std::size_t count = n - length + 1;
            table[k].resize(count);

            for (std::size_t i = 0; i < count; ++i)
                table[k][i] = std::min(table[k - 1][i],
                                       table[k - 1][i + half]);
        }
    }

    std::size_t size() const {
        return table.empty() ? 0 : table[0].size();
    }

    int query(std::size_t l, std::size_t r) const {
        assert(l < r && r <= size());
        const std::size_t length = r - l;
        const unsigned k = unsigned(std::bit_width(length) - 1);
        const std::size_t block = std::size_t(1) << k;
        return std::min(table[k][l], table[k][r - block]);
    }
};

std::bit_width(length)-1 is a floor binary logarithm for positive length; rejecting empty intervals before the calculation avoids the zero case. Storing only valid starts makes higher levels progressively shorter, although the total is still $\Theta(n\log n)$ integers.

The query performs two data-dependent loads. They are independent, so an out-of-order core can issue them together, but a cache miss still dominates the handful of arithmetic instructions. Keeping every level in a separate contiguous allocation is simple; one flat allocation plus level offsets can reduce allocator metadata and improve control over alignment.

#Paying Less Memory

For $n=10^8$, even four bytes per element per level is too much. A practical compromise divides the input into blocks, stores one minimum per block, and builds a sparse table only over those minima.

A query scans at most two partial edge blocks and uses one constant-time query for all complete blocks in the middle:

#include <limits>

class BlockedRMQ {
    static constexpr std::size_t B = 64;

    std::vector<int> values;
    SparseRMQ blocks;

    static std::vector<int> block_minima(const std::vector<int>& a) {
        std::vector<int> result;
        result.reserve((a.size() + B - 1) / B);

        for (std::size_t begin = 0; begin < a.size(); begin += B) {
            std::size_t end = std::min(begin + B, a.size());
            auto first = a.begin() + static_cast<std::ptrdiff_t>(begin);
            auto last = a.begin() + static_cast<std::ptrdiff_t>(end);
            result.push_back(*std::min_element(first, last));
        }
        return result;
    }

public:
    explicit BlockedRMQ(std::vector<int> input)
        : values(std::move(input)), blocks(block_minima(values)) {}

    int query(std::size_t l, std::size_t r) const {
        assert(l < r && r <= values.size());
        int result = std::numeric_limits<int>::max();

        while (l < r && l % B != 0)
            result = std::min(result, values[l++]);

        const std::size_t full_end = r - r % B;
        if (l < full_end) {
            result = std::min(result, blocks.query(l / B, full_end / B));
            l = full_end;
        }

        while (l < r)
            result = std::min(result, values[l++]);
        return result;
    }
};

The auxiliary table contains $\lceil n/B\rceil$ values rather than $n$. A query performs $O(B)$ scalar work—at most $2B-2$ edge elements—plus two table loads. With a fixed $B$ this is constant in $n$, but the constant is real. Choose $B$ from the memory budget and query distribution, and vectorize the edge reductions if they become important.

For short ranges, the blocked version scans the entire query and may be faster than touching a distant upper table level. For long ranges, it saves enough memory that the top-level structure is more likely to remain cached. The smaller representation can win even while executing more comparisons.

#Linear Space and Constant Queries

It is possible to achieve all three desirable bounds for static RMQ:

  • $O(n)$ preprocessing time;
  • $O(n)$ space;
  • $O(1)$ query time.

The route goes through Cartesian trees. The Cartesian tree of an array has the minimum at its root and recursively represents the left and right subarrays. An RMQ becomes a lowest-common-ancestor query between two tree positions.

Farach-Colton and Bender reduce LCA to RMQ on an Euler-tour depth sequence whose adjacent values differ by exactly one. Small blocks of such a $\pm1$ sequence have only a limited number of shapes, so all within-block answers can be tabulated by shape; a sparse structure over block minima handles the middle. Fischer–Heun generalizes the microblock idea directly to RMQ.

The asymptotics are optimal, but the implementation has more tables, encodings, and indirections than the blocked structure above. It pays off when memory is constrained and the query count is large. “Optimal” is a statement about a model; the crossover is an experimental fact.

#Returning Positions and Handling Ties

Many applications need the index of a minimum, not only its value. Store pairs (value,index) and define one total order, such as smaller value first and smaller index on ties. Every build and query operation must use the same order. If one layer chooses the leftmost minimum and another the rightmost, overlapping sparse-table queries can return inconsistent positions even though the minimum value is correct.

NaNs require a similar policy for floating-point arrays. std::min is not a mathematical total order over NaNs; decide whether a NaN propagates, is ignored, or is ordered explicitly, and test that contract.

#Testing and Workloads

For small arrays, enumerate every nonempty interval and compare with a direct scan. Include equal values, monotone arrays, alternating extremes, lengths around powers of two, and arrays whose size is just below or above a block boundary. Randomized tests should vary both values and query lengths.

Performance depends heavily on the query distribution. Uniform random endpoints favor long ranges; many applications issue mostly short, nearby ranges. Report preprocessing time, bytes per element, and cold and warm query latency separately. If only a few queries are made, scanning can be faster than building any structure at all.

RMQ is a good example of optimization by algebra. Idempotence permits overlapping intervals; that removes a branchy decomposition from every query. Blocking then spends a bounded amount of arithmetic to buy locality and a much smaller index. The fastest structure follows from the operation’s laws and the machine’s memory hierarchy together.
