Search Trees

A static index can spend linear preprocessing time on a perfect layout. A search tree cannot: after every insertion it must still be searchable, balanced, owned, and within its allocation bounds.

The natural continuation of the static B+ layout is therefore not “add a few pointers.” Updates introduce a larger contract:

  • which keys are legal, and how duplicates are ordered;
  • minimum and maximum node occupancy;
  • who owns nodes and whether their addresses remain stable;
  • how separator keys change after a child changes;
  • what happens when the root splits;
  • which iterator or pointer guarantees the container provides.

This chapter develops an insertion-only B+ multiset for signed 64-bit keys. It is intentionally smaller than a standard-library container, but every operation shown is complete.

#Fence Keys and Routing

Leaves contain the data. An internal node with $c$ children stores $c$ fence keys, where fence $i$ is the maximum key in child subtree $i$. This differs slightly from the common representation with $c-1$ separators, but it makes routing explicit:

$$ i=\operatorname{lower\_bound}(\text{fences},x). $$

For lookup, no such $i$ means the entire subtree is smaller than $x$. For insertion, a key larger than every fence belongs in the last child.

Duplicates use multiset semantics. Lookup follows the first fence not less than the query and therefore reaches the leftmost subtree that can contain an equal key. Insertion uses upper_bound inside the selected leaf, placing the new copy after equal keys already in that leaf. Equal keys may span several leaves; the global leaf order remains nondecreasing.

No sentinel is needed. In particular, INT64_MAX is an ordinary key rather than a marker for an unused slot.

#Occupancy and Height

Let a leaf hold at most $L$ keys and an internal node at most $F$ children. The implementation uses even $L$ and $F$ and splits a full node in half before descending into it.

After the first split:

  • every non-root leaf contains between $L/2$ and $L$ keys;
  • every non-root internal node contains between $F/2$ and $F$ children;
  • an internal root contains between two and $F$ children;
  • all leaves stay at the same depth.

The last property follows because only the root can create a new level, and it raises every old leaf by exactly one.

If the height $H$ counts both root and leaf, a nontrivial tree contains at least

$$ 2\left(\frac{F}{2}\right)^{H-2}\frac{L}{2} =L\left(\frac{F}{2}\right)^{H-2} $$

keys. Thus height is $O(\log_F n)$ for fixed occupancy constants. Claims based on every node being full are capacity bounds, not worst-case height bounds.

#Ownership and Physical Layout

The reference implementation owns nodes with std::unique_ptr in an arena and stores raw pointers only as non-owning child references. Moving the arena’s vector moves the smart pointers, not the separately allocated nodes, so child addresses remain stable. Destruction is automatic and every node has exactly one owner.

This layout favors clarity, not minimum allocation overhead. alignas(64) aligns each node but does not imply that sizeof(node) is 64 bytes: pointer width, array sizes, count fields, and tail padding remain platform properties. A production tree can replace the arena with slabs while preserving the same ownership graph.

Indices can replace pointers in a relocatable arena, but the index type must cover every allocated node and every byte offset. A fixed int arena and unchecked node_count * node_size calculation are not valid capacity policies.

#A Checked Reference Implementation

Top-down splitting keeps the current node non-full. Every split allocates its right sibling before modifying the tree; with fixed-size integer arrays, no later step in that split allocates or copies a throwing key type.

#include <algorithm>
#include <array>
#include <cstddef>
#include <cstdint>
#include <limits>
#include <memory>
#include <optional>
#include <stdexcept>
#include <vector>

template <std::size_t LeafCapacity = 32,
          std::size_t Fanout = 16>
class bplus_multiset_i64 {
    static_assert(LeafCapacity >= 4 && LeafCapacity % 2 == 0);
    static_assert(Fanout >= 4 && Fanout % 2 == 0);

    static constexpr std::size_t key_slots =
        LeafCapacity > Fanout ? LeafCapacity : Fanout;

    struct alignas(64) node {
        bool leaf = true;
        std::size_t count = 0;
        std::array<std::int64_t, key_slots> keys{};
        std::array<node*, Fanout> children{};
    };

public:
    bplus_multiset_i64() {
        root_ = make_node(true);
    }

    bplus_multiset_i64(const bplus_multiset_i64&) = delete;
    bplus_multiset_i64&
    operator=(const bplus_multiset_i64&) = delete;
    bplus_multiset_i64(bplus_multiset_i64&&) noexcept = default;
    bplus_multiset_i64&
    operator=(bplus_multiset_i64&&) noexcept = default;

    void insert(std::int64_t key) {
        if (size_ == std::numeric_limits<std::size_t>::max())
            throw std::length_error("tree size overflow");

        if (is_full(*root_))
            split_root();
        insert_nonfull(*root_, key);
        ++size_;
    }

    std::optional<std::int64_t>
    lower_bound(std::int64_t key) const noexcept {
        if (size_ == 0)
            return std::nullopt;

        const node* current = root_;
        while (!current->leaf) {
            const std::size_t child = lower_bound_slot(*current, key);
            if (child == current->count)
                return std::nullopt;
            current = current->children[child];
        }

        const auto first = current->keys.begin();
        const auto last =
            first + static_cast<std::ptrdiff_t>(current->count);
        const auto found = std::lower_bound(first, last, key);
        if (found == last)
            return std::nullopt;
        return *found;
    }

    std::size_t size() const noexcept {
        return size_;
    }

    std::size_t height() const noexcept {
        std::size_t result = 1;
        const node* current = root_;
        while (!current->leaf) {
            ++result;
            current = current->children[0];
        }
        return result;
    }

    std::size_t node_count() const noexcept {
        return arena_.size();
    }

private:
    node* make_node(bool leaf) {
        auto owned = std::make_unique<node>();
        owned->leaf = leaf;
        node* const result = owned.get();
        arena_.push_back(std::move(owned));
        return result;
    }

    static bool is_full(const node& value) noexcept {
        return value.count
            == (value.leaf ? LeafCapacity : Fanout);
    }

    static const std::int64_t&
    maximum(const node& value) noexcept {
        return value.keys[value.count - 1];
    }

    static void refresh_fences(node& value) noexcept {
        if (value.leaf)
            return;
        for (std::size_t i = 0; i < value.count; ++i)
            value.keys[i] = maximum(*value.children[i]);
    }

    static std::size_t
    lower_bound_slot(const node& value,
                     std::int64_t key) noexcept {
        const auto first = value.keys.begin();
        const auto last =
            first + static_cast<std::ptrdiff_t>(value.count);
        return static_cast<std::size_t>(
            std::distance(first, std::lower_bound(first, last, key))
        );
    }

    static std::size_t
    insertion_child(const node& value,
                    std::int64_t key) noexcept {
        const std::size_t slot = lower_bound_slot(value, key);
        return slot == value.count ? value.count - 1 : slot;
    }

    void split_child(node& parent, std::size_t child_index) {
        node& child = *parent.children[child_index];
        node* const right = make_node(child.leaf);

        if (child.leaf) {
            constexpr std::size_t middle = LeafCapacity / 2;
            right->count = child.count - middle;
            for (std::size_t i = 0; i < right->count; ++i)
                right->keys[i] = child.keys[middle + i];
            child.count = middle;
        } else {
            constexpr std::size_t middle = Fanout / 2;
            right->count = child.count - middle;
            for (std::size_t i = 0; i < right->count; ++i)
                right->children[i] = child.children[middle + i];
            child.count = middle;
            refresh_fences(child);
            refresh_fences(*right);
        }

        for (std::size_t i = parent.count;
             i > child_index + 1;
             --i)
            parent.children[i] = parent.children[i - 1];

        parent.children[child_index + 1] = right;
        ++parent.count;
        refresh_fences(parent);
    }

    void split_root() {
        node* const old_root = root_;
        node* const replacement = make_node(false);
        replacement->count = 1;
        replacement->children[0] = old_root;
        refresh_fences(*replacement);

        split_child(*replacement, 0);
        root_ = replacement;
    }

    void insert_nonfull(node& current, std::int64_t key) {
        if (current.leaf) {
            const auto first = current.keys.begin();
            const auto last =
                first + static_cast<std::ptrdiff_t>(current.count);
            const std::size_t slot = static_cast<std::size_t>(
                std::distance(
                    first,
                    std::upper_bound(first, last, key)
                )
            );

            for (std::size_t i = current.count; i > slot; --i)
                current.keys[i] = current.keys[i - 1];
            current.keys[slot] = key;
            ++current.count;
            return;
        }

        std::size_t child_index = insertion_child(current, key);
        if (is_full(*current.children[child_index])) {
            split_child(current, child_index);
            child_index = insertion_child(current, key);
        }

        insert_nonfull(*current.children[child_index], key);
        refresh_fences(current);
    }

    std::vector<std::unique_ptr<node>> arena_;
    node* root_ = nullptr;
    std::size_t size_ = 0;
};

There are no duplicate function definitions, hidden global height, or fixed ten-element path stack. The recursion depth is the actual tree height. Every array write is bounded by the top-down invariant: a leaf has fewer than $L$ keys before insertion, and an internal parent has fewer than $F$ children before a split inserts a new child.

The maximum-fence representation duplicates one key per child. refresh_fences is called after every recursive insertion and after both halves of an internal split, so routing never uses a stale subtree maximum.

#What This Container Does Not Promise

The implementation supports insertion and lower-bound lookup. It does not yet provide deletion, iterators, concurrency, persistence, or exception guarantees for arbitrary user-defined key types—the key type is deliberately fixed to a non-throwing integer.

It also does not provide pointer stability for elements. Splitting a leaf copies keys into another node, so a pointer to a key is not a stable handle. Stable references generally require indirection, which changes memory use and lookup locality.

Range iteration would usually add links between leaves. Deletion would borrow from or merge with a sibling when occupancy falls below half, repair all affected fences, and possibly remove an internal root with one remaining child. These are structural operations, not details that can be omitted while still claiming a full std::multiset replacement.

#SIMD and Update Costs

The scalar local lower bound is intentionally isolated. For 32-bit keys, the valid-lane mask technique from the static-tree SIMD section can replace it. For 64-bit keys, AVX2 compares four lanes per 256-bit register rather than eight. In either case:

  • intrinsics require a target-specific build and runtime dispatch when older CPUs are supported;
  • mask extraction must ignore unused lanes rather than fill them with a reserved key;
  • node alignment and cache-line boundaries must be measured from the actual sizeof(node);
  • wider nodes reduce height but make insertion shifts and splits more expensive.

Searches often dominate mixed workloads, but updates serialize more strongly because one operation changes the path used by the next. Report lookup and insertion separately, along with their ratio, key distribution, duplicate rate, tree height, occupancy histogram, allocation policy, and whether queries are independent.

Historical speedup graphs from one compiler and processor cannot establish a portable factor over std::set or another B-tree. A fair comparison includes construction and memory, matches multiset semantics, uses the same key sequence, and distinguishes reciprocal throughput from dependency-chained latency.
