Algorithms for Modern Hardware

Algorithms for Modern Hardware is an open-source book by Sergey Slotin about performance engineering and practical algorithm design.

It is intended for readers ranging from undergraduate computer-science students to performance engineers and algorithm researchers: anyone who wants to understand not only how many abstract operations an algorithm performs, but how those operations travel through a modern machine.

The book source is hosted in the Algorithmica repository, with companion experiments in a separate code repository.

FAQ

Bug and typo fixes. The preferred way to report a problem is to fix the source directly through the edit link on each page or open a pull request on GitHub. You can also create an issue or contact the author. A useful technical report includes a minimal counterexample, the affected machine or compiler when relevant, and a primary source.

What does a release mean for an open-source book? The web edition can improve continuously. A release-quality part has all essential sections present, a stable table of contents, completed technical and copyediting passes, reproducible code, cleared illustration rights, and a print-oriented build. Later corrections and changes reflecting new hardware or algorithms can still be incorporated.

Can the web version disappear behind a paywall? The project has committed to keeping the web version freely available. Sharing it and contributing corrections are the most direct ways to support it.

Translations. Independent translations of individual articles are welcome. Because technical chapters evolve, a translation should record the source revision it follows so later corrections can be merged deliberately. The articles at ru.algorithmica.org/cs/ cover mostly classical computer-science algorithms and are not simply a Russian edition of this performance-engineering part.

Why teach performance engineering after algorithms? The standard asymptotic model remains indispensable, but computers have changed substantially since the canonical algorithm textbooks were written. Modern algorithm design also has to account for parallel execution inside a core, memory hierarchy, vector instructions, compilation, and the real input range. Courses such as MIT’s Performance Engineering of Software Systems, Aalto University’s Programming Parallel Computers, and the independent Performance Ninja curriculum demonstrate how these topics can be taught systematically.

Part I: Performance Engineering

Part I covers the architecture and optimization of single-threaded CPU algorithms. Short examples introduce caching, instruction-level parallelism, arithmetic transformations, profiling, compilation, and SIMD. Larger case studies then combine these mechanisms in complete algorithms and data structures.

Measured speedups in the case studies are evidence from the named processor, compiler, and workload—not promises for every machine. The durable result is the causal explanation and the method used to reproduce it.

Part I concludes with a performance engineering checklist and a probability and measurement appendix.

Later Parts

The broader roadmap includes parallel algorithms; distributed systems and communication-constrained algorithms; and the software–hardware boundary, including compiler back ends, JIT compilation, GPUs, FPGAs, and specialized accelerators. These subjects remain separate from Part I’s single-threaded completion boundary.

Technology Choices

Examples primarily use C++, GCC or Clang, and x86-64 because they expose the mechanisms under discussion and are widely available. The principles are broader than this stack; the exact instructions, ABI, compiler behavior, and performance figures are not.
