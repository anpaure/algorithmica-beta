Prefetching

If a future address is known early, the memory system can start fetching its line before the program needs the value. This prefetching converts latency into an overlapped request and consumes some of the memory-level parallelism available in the machine.

Ordinary out-of-order execution already does this for independent loads in the instruction window. Two additional mechanisms reach farther:

  • hardware prefetchers recognize address patterns in the stream of cache misses;
  • software prefetch instructions give the processor a hint about a particular future address.

Both are speculative performance mechanisms. They can reduce latency, but they also consume request entries, cache capacity, translation resources, and bandwidth.

#Hardware Prefetching

Modify the random-cycle benchmark so that it visits cache lines in increasing order while visiting the fifteen remaining 32-bit words inside each line in a shuffled order. For $N$ divisible by 16, this constructs one cycle and closes it explicitly:

assert(N >= 16 && N % 16 == 0);

std::vector<std::uint32_t> next(N);
std::array<std::uint32_t, 15> offsets;
std::iota(offsets.begin(), offsets.end(), 1);
std::mt19937 rng(42);

std::uint32_t tail = 0;
for (std::uint32_t base = 0; base < N; base += 16) {
    std::shuffle(offsets.begin(), offsets.end(), rng);

    for (std::uint32_t offset : offsets) {
        next[tail] = base + offset;
        tail = base + offset;
    }

    if (base + 16 < N) {
        next[tail] = base + 16;
        tail = base + 16;
    }
}
next[tail] = 0;

The core still cannot derive the next word from the instruction stream, but the requested line numbers form a simple sequence. On the historical Zen 2 test, the chain took about 3 ns per step over the measured range because the next lines usually arrived before use.

Prefetcher behavior is microarchitecture-specific. Many processors recognize one or more forward or backward streams and some fixed strides, but limits on stream count, stride, page crossing, and destination cache differ. Treat the flat result as a demonstration from one machine, not a promise that every linear-looking traversal is prefetched.

#Software Prefetching

GCC and Clang expose a prefetch hint through __builtin_prefetch:

__builtin_prefetch(a.data() + index, 0, 1);

The optional arguments describe a read (0) and low temporal locality (1). The GCC documentation is deliberately cautious: the compiler emits a target instruction if one exists, and the processor may treat it as a hint. The prefetch instruction itself is normally non-faulting on supported targets, but evaluating the address expression can still fault or invoke undefined behavior. Form an address inside a live allocation.

For an artificial pointer chain, we want a permutation that is irregular enough not to look like a normal stride but whose future state is cheap to compute. A full-period linear congruential map works if its parameters satisfy the right conditions. The claim that $2x+1$ modulo a prime always has period $n$ is false: its non-fixed orbits have a period dividing the multiplicative order of 2, hence dividing $n-1$.

Instead, choose a power-of-two size $n$ and

$$ f(x) = 5x + 1 \pmod n. $$

The increment is odd and $5-1$ is divisible by four, so the Hull–Dobell full-period conditions hold: every state belongs to one cycle of length $n$. This is useful for the experiment, not an endorsement of the generator’s statistical quality.

if (log_n == 0 || log_n >= 32)
    throw std::invalid_argument("log_n must be in [1, 31]");

const std::uint32_t n = 1u << log_n;
const std::uint32_t mask = n - 1;

auto step = [mask](std::uint32_t x) {
    return static_cast<std::uint32_t>((5ull * x + 1) & mask);
};

std::vector<std::uint32_t> next(n);
for (std::uint32_t x = 0; x < n; ++x)
    next[x] = step(x);

Prefetching the immediate successor gives only one iteration of lead time:

std::uint32_t k = 0;
for (std::size_t i = 0; i < steps; ++i) {
    __builtin_prefetch(next.data() + step(k), 0, 1);
    k = next[k];
}

#Jumping Ahead Safely

Affine maps compose. Rather than using 1 << D—which becomes undefined when the shift reaches the type width and overflows much earlier in intermediate arithmetic—we can exponentiate the affine transformation by squaring:

struct Affine {
    std::uint32_t mul;
    std::uint32_t add;
};

Affine compose(Affine f, Affine g, std::uint32_t mask) {
    // f(g(x))
    return {
        static_cast<std::uint32_t>((std::uint64_t{f.mul} * g.mul) & mask),
        static_cast<std::uint32_t>(
            (std::uint64_t{f.mul} * g.add + f.add) & mask)
    };
}

Affine power(Affine f, std::size_t exponent, std::uint32_t mask) {
    Affine result{1, 0};
    while (exponent != 0) {
        if (exponent & 1)
            result = compose(f, result, mask);
        f = compose(f, f, mask);
        exponent >>= 1;
    }
    return result;
}

std::uint32_t apply(Affine f, std::uint32_t x, std::uint32_t mask) {
    return static_cast<std::uint32_t>(
        (std::uint64_t{f.mul} * x + f.add) & mask
    );
}

Compute Affine ahead = power({5, 1}, D, mask) once, then prefetch next.data() + apply(ahead, k, mask) on each iteration. After the initial warm-up, each hint is aimed $D$ dependent steps ahead.

Increasing $D$ does not multiply throughput by $D$. The speedup stops when the lead time covers the miss latency or when request queues, issue bandwidth, cache capacity, translations, or DRAM bandwidth saturate. Prefetching too far can evict the line before use; a wrong-path hint may waste all of its traffic.

This is why software prefetching often fails in production. It is most attractive when the future address is reliable, there is useful computation between the hint and the load, and profiling shows latency rather than bandwidth is the bottleneck.

The x86 _mm_prefetch intrinsic also accepts hints such as _MM_HINT_T0, _MM_HINT_T1, _MM_HINT_T2, and _MM_HINT_NTA. These encodings express intended locality; they do not portably command an exact cache level, and a processor may ignore or reinterpret them. Hardware prefetchers are not harmless either: good designs throttle them under pressure, but an unnecessary stream can still evict useful lines and consume bandwidth.
